# Zing 기능 명세서

병렬 작업(백엔드/프론트) 시 서로 안 부딪히기 위한 기준 문서. 항목이 바뀌면 여기부터 업데이트하고, 코드는 그 기준을 따라간다.

## 1. 화면 목록

| 화면 | 설명 | 담당 |
|---|---|---|
| 회원가입 | 계정 생성, 성별 비공개(자율 선택) | 서희 |
| 로그인 | 이메일+비밀번호 로그인 | 서희 |
| 일기 작성 | 200~600자 검증 | 서희 |
| 피드 | 랜덤 일기 넘겨보기, 징 보내기 | 서희 |
| 매칭 목록 | 상호 징 성사된 상대 목록 | 서희 |
| 상대방 일기 상세 | 매칭된 상대 일기, 반응/댓글 | 서희 |
| 프로필 | 내 정보 관리 | 서희 |
| 채팅 | 제한적 소통 (로드맵 마지막 단계) | 서희 |
| 알림 | 매칭 성사/반응 등 이벤트 | 서희 |

(화면별 와이어프레임은 Figma 참고 — 링크 추가 예정)

## 2. 데이터 모델 (테이블 스키마)

> 아래는 초안. 실제 Supabase 테이블 만들 때 이 표부터 채우고 시작.

### `users`
| 필드 | 타입 | 설명 |
|---|---|---|
| id | uuid | PK, Supabase Auth `auth.users.id`와 동일 값 참조 |
| nickname | text | 화면에 보여줄 이름 (실명 아님) |
| gender | text \| null | `'male'` \| `'female'` \| `null`(비공개, 자율 선택) |
| is_exchange_student | boolean | 교환학생 여부 — 매칭/번역 방향 결정에 필요 |
| nationality | text \| null | 국적 (번역 언어 결정에 참고) |
| preferred_language | text | 일기 작성/번역 기준 언어 (예: `'ko'`, `'en'`) |
| profile_image_url | text \| null | 프로필 이미지 (없으면 기본 이미지) |
| created_at | timestamp | 가입일 |

### `diaries`
| 필드 | 타입 | 설명 |
|---|---|---|
| id | uuid | PK |
| author_id | uuid | FK → `users.id` |
| content | text | 200~600자 검증 (프론트+DB 양쪽에서 체크) |
| char_count | int | `content` 글자 수 (검증/표시용으로 별도 저장) |
| created_at | timestamp | 작성일 |
| updated_at | timestamp \| null | 수정 시 갱신 |

> **미정**: "매칭 전 절반만 공개" 로직을 위한 필드는 아직 안 넣음 — 글자 수 기준인지 문단 기준인지(09-03 노트 미정 항목) 정해지면 그때 `public_preview` 같은 필드 또는 앱 로직(예: `content.slice(0, N)`)으로 처리할지 결정.

## 3. API 계약 (함수 시그니처)

> 백엔드가 프론트에 제공하는 함수 목록. 이름/파라미터/리턴값을 여기서 먼저 정하고 나서 구현.

| 함수 | 파라미터 | 리턴 | 설명 |
|---|---|---|---|
| `signUp` | `{ email, password, nickname, gender, isExchangeStudent, nationality, preferredLanguage }` | `{ data, error }` | 회원가입. Auth 계정 생성 + `users` 테이블에 프로필 row 생성까지 한 번에 처리 |
| `signIn` | `{ email, password }` | `{ data, error }` | 로그인 |
| `createDiary` | `{ content }` | `{ data, error }` | 일기 작성 (글자수 검증 포함) |
| `getDiaries` | `{ authorId }` | `{ data: Diary[], error }` | 특정 유저의 일기 목록 조회 |
| `updateDiary` | `{ id, content }` | `{ data, error }` | 내가 쓴 일기 수정 (글자수 재검증) |
| `deleteDiary` | `{ id }` | `{ data, error }` | 내가 쓴 일기 삭제 |
| `getFeed` | `{ userId }` | `{ data: Diary[], error }` | 랜덤 피드 목록 |
| `sendZing` | `{ toUserId }` | `{ data, error }` | 징 보내기 |
| `getMatches` | `{ userId }` | `{ data: Match[], error }` | 매칭 목록 |

(실제 구현하면서 계속 추가)

### `signUp` 상세

**파라미터**
| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| email | string | O | 로그인용 이메일 |
| password | string | O | 비밀번호 |
| nickname | string | O | 화면에 보여줄 이름 |
| gender | `'male'` \| `'female'` \| `null` | X | 비공개 선택 시 `null` |
| isExchangeStudent | boolean | O | 교환학생 여부 |
| nationality | string | X | 국적 |
| preferredLanguage | string | O | 예: `'ko'`, `'en'` |

**리턴**
| 필드 | 타입 | 설명 |
|---|---|---|
| data | `{ user, session } \| null` | 성공 시 생성된 유저/세션 정보 |
| error | `{ message, status } \| null` | 실패 시 에러 (이메일 중복 등) |

### `signIn` 상세

**파라미터**
| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| email | string | O | |
| password | string | O | |

**리턴**
| 필드 | 타입 | 설명 |
|---|---|---|
