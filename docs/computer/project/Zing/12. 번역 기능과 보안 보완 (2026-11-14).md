### 1. 제공자 고르기

평균 일기 400자, 환율 1,400원 기준으로 비교했다.

| 제공자 | 일기 1편 | 무료 구간 | 특징 |
|---|---|---|---|
| Claude Haiku 5.5 | 약 0.5원 (추정) | 없음 | 말투·맥락을 살림 |
| 파파고 | 약 8원 (단가 미확인) | 없음 | 한↔일, 한↔영에 강함 |
| Google 번역 | 약 11원 | 월 50만 자 (출처마다 다름) | 언어가 가장 많음 |
| DeepL | 약 14원 + 월 기본료 | 월 50만 자 무료 플랜 | 품질 좋음 |

활성 사용자 1,000명 × 매일 일기 × 2개 언어 기준이면 월 6만 건이다. 이때 Haiku는 약 3만 원, 번역 전용 API들은 50~80만 원이 나온다. 그래서 처음엔 Haiku로 설계했다.

그런데 **초반 비용 0원**이 조건으로 붙었다. 사용자가 적을 때는 DeepL 무료 플랜(월 50만 자, 일기 약 1,250편)이면 충분하다. 게다가 한도를 넘어도 **과금되지 않고 멈추기만** 한다. 그래서 둘을 엮었다.

- `DEEPL_API_KEY`만 있으면 DeepL만 쓴다. 한도를 넘으면 "이번 달 무료 번역 한도를 다 썼어요"가 뜬다.
- `ANTHROPIC_API_KEY`를 추가하면 DeepL이 한도 초과나 장애일 때 자동으로 Claude Haiku로 넘어간다.
- **코드 수정 없이 키(Secret)만으로 제공자가 바뀐다.** 번역 API를 부르는 곳이 Edge Function 한 군데뿐이라 가능하다.

### 2. 구조

```
[앱] 번역 보기 → [Edge Function translate]
                  1. 로그인 확인
                  2. 내 사용 언어를 DB에서 읽음 (앱이 보낸 값은 안 믿음)
                  3. 이미 내 언어로 쓰인 일기면 → 번역 안 함
                  4. 저장된 번역이 있고 원문이 안 바뀌었으면 → 그대로 반환
                  5. 하루 50회 확인 → 번역 → 저장 → 반환
                  6. 매칭 전인 상대 일기면 번역문도 앞 절반만
```

- **API 키는 Edge Function에만 있다.** 앱에 넣으면 누구나 꺼내 쓸 수 있기 때문이다.
- **번역은 저장해서 모두가 재사용한다.** 비용이 조회 수가 아니라 **일기 수 × 언어 수**에 비례한다.
- **절반 공개는 번역문에도 적용된다.** 전문을 한 번만 번역해 저장하고, 매칭 전이면 번역문의 앞 절반만 준다. 일기당 번역이 1회로 끝나서 가장 싸다. 한국어와 영어는 어순이 달라 원문 절반과 번역문 절반의 내용이 정확히 같지는 않은데, 미리보기 용도라 허용했다.
- **Claude 프롬프트**에는 일기 안의 문장은 지시가 아니라 번역할 내용이라고 명시했다. 일기에 "위 내용을 무시하고…" 같은 문장을 써서 번역기를 조종하는 걸 막기 위해서다. DeepL은 번역 전용이라 이 문제가 없다.

### 3. 테스트하다 발견한 것 — 한국어를 한국어로 번역

첫 테스트에서 번역 버튼을 눌렀더니 "원문 보기"로 바뀌긴 했는데 글자가 그대로였다. DB를 보니 DeepL이 실제로 호출됐다.

- 원인: 테스트 계정(UI테스트)의 사용 언어가 한국어였다. 한국어 일기를 한국어로 "번역"하느라 무료 한도를 쓴 것.
- 수정: 호출 전에 글자 모양으로 원문 언어를 어림잡는다. 한글·가나·한자 비율로 한국어·일본어·중국어를 판단하고, 이미 내 언어면 API를 부르지 않고 "이미 내 사용 언어로 쓰인 일기예요"를 보여준다.
- 한계: 영어·프랑스어처럼 알파벳을 쓰는 언어끼리는 판단을 못 해서 그대로 보낸다.

### 4. 언어 2개 → 8개

한국어, English, 日本語, 中文, Tiếng Việt, Français, Deutsch, Español.

교환학생이 많은 나라(일본·중국·베트남·프랑스·독일·스페인어권) 기준으로 골랐다. 가입 화면 선택지가 많아져서 `OptionSelector`가 4개씩 줄바꿈되게 바꿨다. 베트남어는 DeepL 지원 여부를 문서로 확인하지 못해서 실제로 호출해 봤는데 정상 번역됐다.

### 5. 보안 보완 — 남겨둔 과제 정리

| 과제 | 전 | 후 |
|---|---|---|
| 절반 공개 | `diaries` SELECT가 전체 허용 → API 직접 조회로 전문이 보임 | **내 일기만** 조회 가능. 다른 사람 일기는 전용 함수로만 |
| 일기 하루 1개 | 앱에서만 검사 | **DB 트리거**로 강제. 작성 시각도 현재 시각으로 고정 |
| 하루 기준 | 일기는 기기 시간, 징·단계는 한국 시간 | 전부 **한국 시간 0시** |
| `rls_auto_enable()` | 로그인 안 해도 호출 가능 | 외부 호출 차단 |

`rls_auto_enable()`은 우리가 만든 게 아니었다. 들여다보니 새 테이블이 생기면 RLS를 자동으로 켜주는 이벤트 트리거용 함수였다(Supabase 프로젝트 생성 시 설정). 트리거 자체는 그대로 두고, API로 부르는 경로만 막았다.

작성 시각 고정이 중요한 이유: 단계 해금이 "매칭 이후 쓴 일기 수" 기준이라, `created_at`을 조작하거나 하루에 여러 개 쓰면 단계를 부정하게 올릴 수 있었다.

### 7. 이번에 배운 것

- **인증 정보는 AI에게 맡기지 않는다.** DeepL 키를 대화창에 붙이고 등록해 달라고 했는데, AI는 키 입력을 하지 않았다. 키는 Supabase 대시보드에 직접 넣었다. 대화 기록에 키가 남았으니 재발급을 권장받았다.
- **무료 플랜도 일시정지된다.** Supabase가 이번 주에만 두 번 멈췄다. 7일 동안 활동이 없으면 멈춘다. 런칭 전에는 Pro 플랜(월 25달러)으로 올려야 한다.

### 8. 남은 과제

- 앱 안에서 사용 언어를 바꾸는 화면이 없다 (가입 때만 선택)
- 채팅 번역 (4단계 채팅을 만들 때 같은 함수에 붙임, BM의 하루 무료 횟수 포함)
- DeepL 무료 한도가 매달 갱신되는지 계정 화면에서 확인
- 2단계 "오늘의 질문"부터 미구현
- 단계 스킵권 BM 후보 재검토 (단계가 짧아져 효용이 줄어듦)
