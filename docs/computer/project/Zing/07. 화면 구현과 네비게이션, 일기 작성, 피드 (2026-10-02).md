### 1. 회원가입 화면

- 입력: 이메일, 비밀번호, 닉네임, 성별(남/여/비공개), 교환학생 여부, 국적, 사용 언어
- `OptionSelector<T>`: 버튼 중 하나를 고르는 제네릭 컴포넌트. 성별(`'male'|'female'|null`), 교환학생 여부(`boolean`), 언어(`string`)를 **하나의 컴포넌트로** 처리
- 검증 메시지 2종(텍스트 필드 누락 / 선택 항목 누락) 후 `signUp` 호출
- 확인: 가입 후 `users` 테이블에 입력한 값이 그대로 저장됨 (`gender: null` = 비공개)
- 사용 언어는 한국어/English 2개뿐 (임시 목록, 번역 API 정해지면 확장)

### 2. 네비게이션과 세션

- 설치: `@react-navigation/native`, `native-stack`, `bottom-tabs`, `react-native-screens`, `react-native-safe-area-context`, `@react-native-async-storage/async-storage`
- 구조
  ```
  App.tsx  ── 세션 있음? ──┬─ 예 → MainNavigator (하단 탭: 홈 / 일기 쓰기)
                           └─ 아니오 → AuthNavigator (로그인 ↔ 회원가입)
  ```
- **화면 이동 코드를 따로 안 쓴다**: `supabase.auth.onAuthStateChange`로 세션을 구독하면, 로그인 성공/로그아웃이 곧 화면 전환이 된다. 예전의 "TODO: 피드로 이동" 주석이 필요 없어짐.
- `lib/supabase.ts`에 `storage: AsyncStorage`, `persistSession: true` 지정 → 새로고침/앱 재시작 후에도 로그인 유지
- `signOut()` 추가
- 기존 `LoginScreen`/`SignUpScreen`은 `onGoToSignUp` 같은 **props 방식 그대로** 두고, 네비게이터에서 `navigation.navigate`를 연결 → 화면이 네비게이션 라이브러리에 직접 의존하지 않음
- 확인: 로그인 → 홈 자동 이동 / 새로고침 후 유지 / 로그아웃 → 로그인 화면 복귀

### 3. 일기 작성 화면

- 여러 줄 입력창, `n / 600 (최소 200자)` 카운터, 저장 버튼
- 글자 수 규칙(**최소 200 / 최대 600**, 공백 포함)을 **화면이 아니라 `lib`에** 구현
  - `lib/constants.ts`: `DIARY_MIN_LENGTH`, `DIARY_MAX_LENGTH`
  - `lib/diaries.ts`: `validateDiaryLength`를 `createDiary`/`updateDiary` 양쪽에서 호출
  - 이유: 어떤 화면에서 불러도 같은 규칙이 적용되고, 유료 플랜(최대 1200자)을 넣을 때 한 곳만 고치면 됨
- 확인
  | 시나리오 | 결과 |
  |---|---|
  | 9자 입력 | "최소 200자 이상 작성해주세요" |
  | 200자 이상 | 저장 성공, 입력창 초기화 |
  | 같은 날 두 번째 | "오늘은 이미 일기를 작성했습니다" |

### 4. 홈 피드

- 카드: 작성자 닉네임 · 교환학생 여부 · 국적 + 본문 **절반**(글자 수 기준 `slice(0, floor(charCount/2))`, 확정된 규칙) + "매칭하면 전체 일기를 볼 수 있어요"
- 내 일기는 제외, 최신순, 20개, 당겨서 새로고침
- **막힌 지점**: 작성자 정보가 필요한데 `users`의 SELECT 정책이 `auth.uid() = id`(내 정보만)라서 다른 사람 닉네임을 못 읽음
- **선택한 해결: 공개용 뷰 `public_profiles`** (노출 컬럼을 닉네임/국적/교환학생 여부/프로필 이미지로 제한)
  - 대안이던 "users SELECT를 전체 공개"는 `gender` 등 모든 컬럼이 노출돼서 기각
- 뷰 생성 전에는 `Could not find the table 'public.public_profiles'` 에러가 났고, SQL Editor에서 아래 SQL을 실행한 뒤(Success) 정상 동작 확인

```sql
create view public.public_profiles as
select id, nickname, nationality, is_exchange_student, profile_image_url
from public.users;

revoke all on public.public_profiles from anon;
grant select on public.public_profiles to authenticated;
```

> 뷰는 소유자 권한으로 실행돼서 `users`의 RLS를 우회한다 — 이게 의도(노출 컬럼만 제한해서 공개)이지만, 컬럼을 추가할 때마다 "이것도 공개해도 되나?"를 확인해야 함.

### 배운 것 / 겪은 일

- **Supabase 무료 프로젝트는 일정 기간 안 쓰면 자동 일시정지**된다. 증상은 "Failed to fetch" 또는 로그인 불가. 대시보드에서 Resume하면 복구되고, 직후 1~2분은 "Database error querying schema"가 일시적으로 날 수 있음.
- **패키지를 설치하면 Metro(개발 서버)를 재시작해야 할 때가 있다.** 설치 직후 `Unable to resolve module ./useLinkProps.js` 에러가 났는데 파일은 디스크에 있었음 → 서버가 옛 파일 목록을 캐시한 것. `npx expo start --web --clear`로 해결. 이전 서버 프로세스가 8081 포트를 잡고 있으면 먼저 종료해야 함.
- **로직 / 구조 / 스타일을 나눠서 생각한다**: 디자인(Figma)이 없어도 로직은 제대로, 스타일은 최소한으로 만들고 디자인이 나오면 스타일만 교체. 색/간격은 나중에 `theme.ts`로 모으기.
- **규칙은 화면이 아니라 `lib`에**: 글자 수 검증처럼 정책에 해당하는 것은 호출 위치와 무관하게 적용되도록.
- 작업 중 `lib/auth.ts`를 실수로 덮어써서 `git checkout`으로 복구한 일이 있었다 → 이미 커밋된 파일은 복구가 가능하니 **자주 커밋**하는 게 안전망.
