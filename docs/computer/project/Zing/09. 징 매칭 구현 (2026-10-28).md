### 1. 구조 — 왜 DB 함수로 만들었나

징 규칙(중복 금지, 매칭 상한, 하루 3회, 일기 첨부)을 프론트에서 검사하면, 앱을 거치지 않고 Supabase API를 직접 호출해서 우회할 수 있다. 그래서:

- `zings` 테이블에는 **SELECT 정책만** 둠 (내가 보냈거나 받은 row만).
- INSERT/UPDATE 정책은 아예 없음 → 쓰기는 `security definer` 함수(`send_zing`, `decline_zing`)로만 가능.
- 프론트는 `supabase.rpc('send_zing', ...)`를 호출하고 결과만 믿음. 함수 안에서 `raise exception '오늘 보낼 수 있는 징(3회)을 다 썼어요...'`처럼 던지면 클라이언트에 `error.message`로 그대로 옴 → 화면에 바로 표시.

CLAUDE.md의 "권한 규칙은 가능한 RLS/Postgres 함수로 강제하고, 프론트는 그 결과를 신뢰한다" 원칙을 처음 제대로 적용한 기능.

**동시성**: A와 B가 거의 동시에 서로 징을 보내면, 둘 다 "상대 징 없음"으로 판단해 매칭이 안 될 수 있다. `pg_advisory_xact_lock`으로 두 사람 쌍 단위로 잠가서 순서대로 처리.

### 2. 기획 수정 — 받은 징을 숨기면 매칭이 안 된다

처음 구현은 "누가 나에게 징을 보냈는지는 안 보임"이었다. 그런데 이러면 **둘이 우연히 서로를 골라야만** 매칭되는데, 피드가 랜덤이면 그럴 확률이 거의 없다.

→ 받은 징은 받은 사람에게 보이게 바꾸고, 매칭 탭에서 수락/거절하도록 수정.

- **수락** = 보낸 사람에게 징을 보내는 것과 같음 (`acceptZing`이 내부적으로 `sendZing` 호출). 하루 횟수에는 포함 안 됨 (`is_response = true`).
- **거절**은 보낸 사람에게 알리지 않음. 보낸 쪽엔 계속 "징을 보냈어요"로 보인다. 거절당했다는 상처를 주지 않기 위해.
- 거절했던 사람이 나중에 마음 바꿔 징을 보내면 바로 매칭.

---

### 3. 징에 일기 첨부 — 그 일기만 보고 결정

받은 징을 수락할지 판단할 근거가 필요했다. 피드는 절반 공개라 정보가 부족하고, 보낸 사람의 전체 일기를 다 보여주면 매칭 전 절반 공개 원칙이 깨진다.

→ **징을 보낼 때 내 일기 하나를 골라서 같이 보내고, 받은 사람은 그 일기(전체 공개)만 보고 수락/거절.**

- 일기가 하나도 없으면 징을 못 보냄 ("먼저 일기를 써야 징을 보낼 수 있어요"). 글을 안 쓰고 징만 뿌리는 걸 막는 효과도 있음.
- 첨부 일기를 나중에 지우면 `diary_id`가 null이 됨 (`on delete set null`) → "함께 보낸 일기가 삭제됐어요" 표시.
- 피드 카드에는 수락 버튼을 두지 않고 "매칭 탭에서 확인하세요"만 안내. 판단 근거를 첨부 일기 하나로 통일하기 위해.

### 4. 화면

- **피드(홈)**: 상단에 "오늘 보낼 수 있는 징 n회". 카드 상태별 표시 — 징 보내기 / 징을 보냈어요 / OO님이 일기와 함께 징을 보냈어요 / 매칭된 상대예요(전체 공개).
- **일기 선택 창(`ZingSendModal`)**: 내 일기 목록, 최신 일기가 기본 선택.
- **매칭 탭(`MatchesScreen`)**: 동시 매칭 n/상한 · 남은 징 → 받은 징 카드(첨부 일기 + 수락/거절) → 매칭된 상대 목록(현재 단계 표시).
- 탭에 들어올 때마다 새로 불러오도록 `useFocusEffect` 사용 (다른 탭에서 매칭이 생겼을 수 있음).

### 6. 테스트 중 잡은 버그 — "Invalid Date"

일기 선택 창의 날짜가 전부 "Invalid Date"로 나왔다.

- 원인: DB는 `created_at`(snake_case), 앱 타입은 `createdAt`(camelCase)인데, 기존 `getDiaries`가 `data as Diary[]`로 **캐스팅만** 하고 있었다. TS는 캐스팅을 믿으니 타입 체크는 통과하지만 실제 값은 `undefined` → `new Date(undefined)`.
- 지금까지 안 드러난 이유: 이 값을 화면에 쓰는 곳이 없었음.
- 수정: 변환 함수 `toDiary(row)`를 만들어 `createDiary`, `getDiaries`, `updateDiary`, 피드에 모두 적용.
- 교훈: **`as`는 변환이 아니라 "믿어줘"일 뿐.** DB row는 반드시 매퍼를 거칠 것.
