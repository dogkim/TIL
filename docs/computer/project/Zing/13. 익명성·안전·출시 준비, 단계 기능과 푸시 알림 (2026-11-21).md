번역 이후 남은 것들을 한꺼번에 채웠다. 비슷한 앱(모씨, 어라운드)을 보고 **가벼운 진입과 익명성**을 보강했고, 스토어에 올릴 수 있는 수준인지 보안 위주로 점검했다. 그다음 테스터를 받을 수 있게 2~4단계 소통과 푸시 알림까지 만들었다.

### 1. 비슷한 앱에서 가져온 것

| 앱 | 본 것 | Zing에 적용 |
|---|---|---|
| 모씨 | 익명으로 글을 올리고 공감을 주고받음 | 매칭 전에는 닉네임 대신 "일본 교환학생"처럼 표시 |
| 어라운드 | 글을 읽으려면 먼저 공감을 남기는 구조 | 새 징을 보내려면 오늘 다른 일기 3개에 반응 |
| 둘 다 | 가입이 가벼움 | 가입 2단계, 국적·지역은 선택 |

- **가입 필수**: 닉네임(직접 지음), 학생 구분, 읽을 언어. **선택**: 국적(공개/비공개), 지역. 성별 항목은 없앴다.
- 국적을 비공개로 하면 "교환학생"으로만 보인다. 비공개 국적은 DB 함수가 `null`로 바꿔서 내보내므로 API를 직접 불러도 안 보인다.
- 반응 3개 조건은 **받은 징 수락에는 적용하지 않았다.** 상대가 이미 관심을 보낸 경우라 막을 이유가 없다.

### 2. 신고·차단

- **차단**: 방향과 상관없이 서로 안 보이게 한다. 피드에서 제외, 징·반응 불가, 진행 중이던 매칭은 끝낸다(기록은 남김).
- **신고**: 사유를 고르면 자동으로 차단까지 된다. 서로 다른 3명이 신고한 일기는 운영자 확인 전에도 피드에서 숨긴다.
- 피드 카드, 받은 징, 교환일기 화면 위쪽 세 군데에 신고 버튼이 있다.
- **운영자 처리**는 Supabase SQL Editor에서만 한다. `admin_report_queue`로 보고 `admin_hide_diary`, `admin_suspend_user`, `admin_resolve_reports`로 처리한다. 앱에서 부르면 401이다. Apple은 신고를 24시간 안에 처리하라고 요구한다.

### 6. 푸시 알림

```
징 도착 / 매칭 / 새 메시지 / 새 질문
   → DB 트리거 → send_push() → pg_net으로 Expo 푸시 API 호출 → FCM(Android)·APNs(iOS) → 폰
```

- **서버를 따로 두지 않았다.** Expo 푸시 API는 인증 없이 토큰만으로 보낼 수 있다. 그래서 DB 트리거가 `pg_net`(비동기 HTTP)으로 바로 부른다. 비동기라 알림이 실패해도 메시지 저장은 막히지 않는다.
- **알림 문구는 익명**이다. 닉네임·일기·메시지 내용을 넣지 않는다. 잠금 화면에 보이기 때문이다.
- 같은 사람이 2분 안에 또 보낸 메시지는 알리지 않는다. 채팅에서 알림이 쏟아지는 걸 막는다.
- 설정에서 끌 수 있고, 로그아웃하면 그 기기 토큰을 계정에서 떼어낸다.
- **Android Expo Go에서는 안 된다.** SDK 53부터 Expo Go에서 원격 푸시가 빠졌다. `expo-notifications`를 Android Expo Go에서 불러오기만 해도 오류를 내서, 필요할 때만 불러오도록 했다. 실제 확인은 `eas init` → FCM 키 등록 → `eas build`로 APK를 만든 뒤에 한다.
- 테스트: 가짜 토큰으로 보내 Expo 서버가 `DeviceNotRegistered`로 응답하는 것까지 확인했다. 연속 메시지 두 개에 요청 1건만 나가는 것도 확인했다.

**테스트하다 헷갈린 것**: 메시지 두 개를 SQL 한 문장(`insert ... select ... generate_series(1,2)`)으로 넣었더니 알림이 하나도 안 나갔다. 행 단위 AFTER 트리거는 문장이 끝난 뒤에 실행된다. 그래서 두 행이 서로를 "2분 안에 보낸 메시지"로 보고 둘 다 건너뛴 것이다. 실제 앱은 메시지를 하나씩 보내서 문제없다.

### 7. Heyring과 비교

AI 전화영어 앱 Heyring은 매일 5분을 무료로 준다. AI 음성은 1분마다 비용이 들어서, 매일 쓰는 무료 사용자 한 명에 월 수천~수만 원이 든다(추정). 그래서 5분 제한이 꼭 필요하고, 그 지점에서 구독을 권한다.

Zing은 번역을 누를 때만 비용이 들고, 번역은 저장해서 재사용한다. 그래서 핵심 기능을 계속 무료로 줘도 부담이 거의 없다. Zing의 하루 제한(징 2회, 번역 50회)은 비용보다 **분위기와 악용 방지**가 목적이다.

채용 공고(서버: MySQL·AWS, CI/CD·모니터링 강조)에서 가져온 것:
- **CI 추가**: GitHub에 push할 때마다 타입 검사, Expo 설정 검사, 약관 사이트 생성을 자동으로 돌린다.
- **오류 모니터링**은 할 일로 남김 (Sentry 무료 플랜, 계정 필요).
- 서버 구성은 따라가지 않았다. 실시간 AI 음성 서비스와 일기 앱은 필요한 게 다르다.

### 8. 이번에 배운 것

- **규칙은 DB가 지킨다.** 이번에 찾은 구멍은 전부 "앱에서만 검사"한 곳이었다. 앱은 우회할 수 있다.
- **Supabase MCP는 `drop`이 들어간 마이그레이션을 거절한다.** `create or replace`, `create or replace trigger`로 바꿔 쓰면 된다. 함수 안의 `delete`도 거절돼서 차단은 행을 지우지 않고 `matched_at=null`로 매칭만 끝내게 했다.
- **plpgsql 파라미터 이름이 컬럼 이름과 같으면 모호하다는 오류가 난다.** `target_user`, `question_text`처럼 다르게 짓는다.
- **보안 점검(advisor)을 마이그레이션마다 돌린다.** 이번에도 새 함수 4개가 로그인 안 한 사용자에게 열려 있던 걸 잡았다.
