# 또리(DDORI) 프로젝트 정리

> 팀 저장소 4개(ddori-frontend, ddori-backend, ddori-docs, frontend)의 `main` 브랜치와 GitHub PR, 이슈를 읽고 프로젝트 전체를 한 번에 정리했다. 2026-11-28 오전 기준이다. 저장소에서 확인한 것만 적었다.

## 한 줄 소개와 기간

**또리는 어려운 재난문자를 아이가 알아듣는 쉬운 말로 바꿔 주고, 지금 할 일을 하나씩 알려 주고, 아이의 상태를 보호자에게 전해 주는 어린이 재난 대응 도우미다.**

- AWS Career Launchpad 경북대학교 PBL 2팀(GenAI 서비스 트랙, 4명)
- 기간: 2026-11-14 ~ 11-28. 기획 발표 11-20, 아키텍처 발표 11-21, 최종 발표 11-28
- 캐릭터: 아이 곁의 **또또**, 보호자 곁의 **리리**. 둘을 합쳐 "또리"다.
- 또리는 공식 재난문자를 대신하지 않는다. 아이가 공식 재난문자를 이해하고 행동하도록 돕는 보조 서비스다(ddori-docs `PROJECT.md`).

## 문제와 해결

재난문자를 받은 아이에게는 세 가지가 빠져 있다. 또리는 그 세 가지를 하나씩 채운다. 근거 자료와 숫자는 [03. 최종발표 문제 정의 근거](./03.%20최종발표%20문제%20정의%20근거%20(2026-11-28).md)에, 발표에서 한 말은 [04. 최종발표 대본](./04.%20최종발표%20대본%20(2026-11-28).md)에 있다.

| 빠진 것 | 문제 | 또리가 하는 일 |
| --- | --- | --- |
| 1. 이해 | "저지대", "대피 권고"처럼 어른도 헷갈리는 말이 많아 무슨 뜻인지 모른다. | AI가 재난문자를 짧고 쉬운 문장과 단어 풀이로 바꾸고, 소리로도 읽어 준다. |
| 2. 행동 | 뜻을 알아도 지금 무엇을 해야 할지 모른다. | 공식 국민행동요령에서 뽑은 "따라 해요" 행동 카드를 한 단계씩 보여 준다. |
| 3. 연결 | 행동을 해도 안전하다고 알릴 방법이 없고, 보호자는 아이가 어디 있는지 몰라 불안하다. | 아이가 "괜찮아요"나 "도와줘요"를 누르면 보호자에게 바로 가고, "도와줘요"는 위치도 함께 간다. 응답이 없으면 다시 알린다. |

## 주요 기능

화면은 PWA 하나에 역할별 경로(`/child`, `/guardian`, `/admin`)로 나뉜다.

### 아이 화면 (`/child`)

- **홈**: 평소에는 또또와 레벨 진행도가 보인다. 재난 알림이 오면 어느 화면에 있든 홈 알림 화면으로 한 번 보낸다.
- **재난 알림**: 쉬운 말 문장과 단어 풀이, 원문 카드, "소리로 듣기" 버튼(서버 음성이 안 되면 브라우저 음성), "따라 해요" 행동 카드가 나온다. 행동 카드는 지진, 비와 물, 불, 더위 4묶음이다.
- **응답**: "괜찮아요" 또는 "도와줘요". "도와줘요"를 누를 때만 위치 권한을 묻고 위치를 보내며, 119 전화 버튼이 나온다.
- **대피소 탭**: 아이 동네 대피소를 지도와 목록으로 보여 주고, "내 위치로 찾기"를 누르면 가까운 순 정렬과 걸어가는 길을 보여 준다.
- **설정**: 내 정보, 재난 알림 받기(Web Push), 배지 현황, 로그아웃. 재난 중에는 레벨과 배지를 숨긴다.

### 보호자 화면 (`/guardian`)

- **홈**: 카드 하나로 아이 상태를 보여 준다. 대기, 응답 대기, 안전, 긴급 4가지이고, 긴급이면 아이 위치를 지도로 보여 준다. 새로고침 없이 실시간(SSE)으로 바뀐다.
- **기록 탭**: 지난 알림, 아이 응답, 응답 없음(재알림) 기록
- **대피소 탭**: 내 아이 동네의 대피소
- **설정**: 연결된 아이, 아이 연결 코드 재발급, 재난 알림 받기
- **가입**: 보호자가 먼저 가입하고 아이를 등록하면 6자리 연결 코드가 나온다. 아이는 그 코드로 로그인한다(10분, 한 번만).

### 학습 (`/child/learn`)

- **레슨**: 재난 종류별 섹션(지진, 물, 불, 더위)에서 레슨을 하나씩 연다. 앞 레슨을 끝내야 다음 레슨이 열린다.
- **퀴즈**: OX, 객관식, 순서 맞히기. 틀린 문제는 다시 풀고, 처음에 틀린 수에 따라 포인트를 받는다. 30포인트마다 레벨이 오른다.
- **배지**: 첫 레슨 완료 배지와 재난별 배지(섹션 레슨 3개 완료)
- **또또에게 묻기**: 아이 질문에 행동요령 원문을 근거로 답하고, 근거 문장을 "자세히 보기"로 보여 준다. 근거를 못 찾으면 지어내지 않고 모른다고 답한다.
- **재난 중 잠금**: 응답하지 않은 재난 알림이 있으면 학습 탭이 잠기고 홈으로 보낸다. 퀴즈보다 지금 할 행동이 먼저다.

### 관리자 화면 (`/admin`)

- **모의 재난문자**: 지역, 긴급 단계, 재난 종류, 문구를 넣거나 미리 만든 예시를 골라 모의 재난문자를 보낸다. 최근 발송 내역도 본다. 시연에서 알림을 일으키는 장치다.
- **레슨 만들기와 문제 검수**: 섹션을 고르고 주제를 넣으면 AI가 문제 후보를 만든다. 관리자가 검수하고 고친 문제 4개를 레슨으로 저장하면 바로 아이에게 보인다.

## 전체 구조

### 재난문자에서 보호자 화면까지

1. **수집**: EventBridge Scheduler가 수집 Lambda(Python)를 실행하고, Lambda가 재난문자를 SQS에 넣는다.
   - 시드니 리전에서는 정부 재난문자 API에 연결되지 않는다. 그래서 Lambda는 S3에 저장한 과거 실제 재난문자를 보내는 "재생 모드"로 배포했다.
   - 시연에서는 관리자 화면의 모의 재난문자 API가 같은 처리 로직을 부른다.
2. **저장**: EC2의 Spring Boot가 SQS에서 메시지를 받아 일련번호로 중복을 거르고 RDS(PostgreSQL)에 저장한다.
3. **쉬운 말 변환**: Vertex AI Gemini가 쉬운 문장과 단어 풀이를 만든다. 앱 검사기와 Bedrock Guardrail이 원문 밖 내용을 막는다. 막히거나 실패하면 재난 종류별 기본 문장을 쓴다.
4. **알림**: 아이 지역에 맞는 아이와 그 보호자에게 Web Push를 보내고, 보호자 화면에는 SSE 이벤트를 보낸다.
5. **응답**: 아이가 "괜찮아요" / "도와줘요"(+ 위치)를 보내면 CloudFront를 거쳐 EC2가 저장하고, 보호자에게 SSE와 Web Push로 알린다.
6. **무응답 재알림**: 알림을 만들 때 EventBridge Scheduler에 일회성 일정을 건다(기본 3분 뒤, 3분 간격, 최대 2회). 일정이 SQS로 만료 메시지를 보내면, 아직 응답하지 않은 아이와 그 보호자에게 다시 알린다.

- 처음 설계는 생성도 Bedrock 모델이었다. 그런데 새 계정의 Bedrock 모델 호출 할당량이 0이었고, 11-25부터는 계정 접근 제한으로 아예 막혔다. 그래서 생성은 Vertex AI Gemini로 바꾸고, Bedrock은 근거 검색과 출력 검사만 맡겼다(ddori-docs `ARCHITECTURE.md`).

### 설계에 있지만 저장소에는 없는 것

- **Cognito**: ADR 0007에서 Cognito로 정했다. 하지만 백엔드 코드는 Spring Security가 JWT를 직접 발급한다(보호자 24시간, 아이 30일). Cognito 리소스와 코드는 저장소에 없다.
- **Amazon Location Service**: 발표 전까지 지도 리소스와 키가 없었다. 그래서 시연 기간에는 MapLibre + 오픈스트리트맵 타일 + TMAP 보행자 경로로 대신했다(ADR 0012, 제안 상태).
- **전체 아키텍처 그림**: 아직 Vertex AI 전환을 반영하지 않았고, 문서가 그림보다 최신이다.

## 저장소 구성과 협업 방식

저장소는 모두 비공개다. 아래 링크는 팀원만 열린다.

| 저장소 | 역할 | PR | 이슈 |
| --- | --- | --- | --- |
| [ddori-frontend](https://github.com/knu-aws-team2/ddori-frontend) | 지금 쓰는 프론트엔드(PWA). 프론트 배포 스택 포함 | 86 (머지 85, 닫힘 1) | 89 (열림 7, 닫힘 82) |
| [ddori-backend](https://github.com/knu-aws-team2/ddori-backend) | Spring Boot, 수집 Lambda, CloudFormation 템플릿 | 62 (모두 머지) | 58 (열림 3, 닫힘 55) |
| [ddori-docs](https://github.com/knu-aws-team2/ddori-docs) | 공통 문서: 기획, 기능 목록, 평가 기준, 아키텍처, ADR | 0 | 4 (모두 닫힘) |
| [frontend](https://github.com/knu-aws-team2/frontend) | 예전 프론트엔드 저장소. 지금은 쓰지 않는다. | 8 (머지 2, 열림 6) | 19 (열림 18, 닫힘 1) |

PR, 이슈 개수는 2026-11-28 오전에 `gh` 로 센 값이다. GitHub에서 저장소 번호는 PR과 이슈가 같이 쓴다.

- **문서 위치**: 기능, 아키텍처, ADR은 ddori-docs에 둔다. API 명세는 백엔드 Swagger가 원본이고, 프론트는 거기서 타입을 만든다. 같은 내용은 한 곳에만 쓰고 링크로 잇는다.
- **이슈**: 코드가 바뀌는 저장소에 만들고, 제목에 `FEATURES.md`의 기능 ID를 붙인다(예: `[ALERT-04] 아이 응답 저장 API`). 하루 안에 끝낼 크기로 나눈다. 기획 질문과 ADR 논의는 ddori-docs 이슈로 한다. 라벨은 백엔드가 `type:`, `area:`, 프론트가 우선순위 `P0`~`P2`와 `bug`, `enhancement`, `보류`를 쓴다.
- **브랜치**: `main`에 직접 커밋하지 않고 기능 브랜치에서 PR로 머지한다(ddori-docs의 단순 문서 수정만 예외). 이름은 `feat/<기능ID>-<짧은-영문>`이다(예: `feat/ALERT-04-child-response`).
- **커밋**: `type(scope): 한국어 요약`. type은 feat, fix, docs, refactor, test, chore. AI 공동 작성자 표시와 "Generated with ..." 문구는 넣지 않는다.
- **PR 리뷰**: 규칙은 "리뷰 승인 뒤 머지, CI 통과 뒤 머지"다. 조직이 GitHub Free 플랜이라 비공개 저장소에 브랜치 보호를 걸 수 없어서, 머지하는 사람이 Checks를 직접 확인한다. 실제로는 ddori-backend PR 62개 중 38개에 다른 팀원 리뷰가 있었고(승인 23개), ddori-frontend는 86개 중 7개(승인 3개)였다.
- **ADR**: 기술을 고른 이유와 대안을 `decisions/`에 번호를 붙여 남긴다. 결정을 바꿀 때는 옛 ADR을 고치지 않고 새 ADR을 만든 뒤 옛 것을 "대체됨"으로 바꾼다.
- **AI 도구**: 각 저장소에 `CLAUDE.md`와 `AGENTS.md`를 두고, AI 도구와 팀원이 같은 규칙을 따르게 했다.

### 저장소 문서에 적힌 한계

- **실제 재난문자를 받지 못한다.** 시드니 리전에서는 정부 재난문자 API에 연결되지 않아, 과거 실제 문자를 다시 보내는 재생 모드와 모의 재난문자로 시연한다. 실제 문자도 API에 약 10분 늦게 올라온다.
- **대피소 데이터**는 시연 지역인 대구광역시 북구의 지진 옥외대피소 63곳뿐이다.
- **Guardrail의 한국어 한계**: 근거 검사는 원문 밖 내용은 잘 막지만, 원문과 반대로 말하는 문장은 통과시킬 수 있다. 그래서 앱 검사기를 함께 둔다.
- **Web Push**: iOS는 홈 화면에 추가한 PWA(16.4 이상)에서만 받는다. 서버는 알림이 실제로 도착했는지 알기 어렵다.
- **서버 한 대 전제**: SSE 연결과 음성 캐시가 서버 메모리에 있다. 서버를 늘리려면 다시 설계해야 한다. refresh token은 없다.
- **TMAP 키와 위치**: TMAP 키가 빌드 결과에 들어가 공개되고, 대피소 길을 찾을 때 아이 위치가 TMAP(SK)으로 간다. 시연 뒤에는 키를 폐기하고, 계속 운영하면 백엔드가 대신 부르게 바꾼다.
- **설계와 구현의 차이**: Cognito와 Amazon Location Service는 구현하지 않았고, 아키텍처 그림은 Vertex AI 전환 전 상태다.
- **목표 수치**: "3초 안에 이해, 1분 안에 첫 행동"은 계획서의 목표값이고 검증하지 않았다.
- **아이 연령 범위**는 정하지 않았다. 계획서는 초등학생이고, 팀에서는 스마트폰을 가진 아이로 넓히자는 의견이 있었다.
