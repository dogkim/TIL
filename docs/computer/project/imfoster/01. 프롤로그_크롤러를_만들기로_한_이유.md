## 시작 계기: 왜 만드는가? (Motif)
- **시작 계기**
    - 4학년이 되면서 본격적으로 취업 및 진로 준비를 위해 무언가 해야겠다는 필요성을 체감함.
        
- **기존 방식의 문제점 (불편함)**
    - 매일 직접 대학교 공지사항이나 채용 플랫폼을 돌아다니며 정보를 찾아보는 과정이 번거롭고 귀찮음.
    - 주변 사람들이 만들어 둔 기존 자동화 툴을 써보았으나, 내가 원하는 핵심 정보가 누락되어 있거나 필요한 기능이 부족함.
    - 마음에 드는 것만 따로 저장하고, 신청기간에 맞게 알람을 띄우고 싶음!!

- **목표 (해결 방안)**
    - 나에게 철저히 맞춤화된 데이터를 추출할 수 있는 나만의 공지사항/채용 정보 자동화 크롤러를 직접 개발하여 시간 비용을 줄이고 효율성을 높임.

## ## 02. 시스템 구현 방식 (Architecture)

### 1. 핵심 요구사항 및 해결 방안

- **정보의 종류별 분류 및 모듈화**
    - 각 사이트(경북대 공지, 링커리어 등)마다 크롤러 소스코드를 독립된 함수나 클래스로 분리(모듈화).
        
    - 새로운 정보 소스가 추가되더라도 기존 코드를 수정할 필요 없이, 새 크롤러 모듈을 만들어 디스코드의 특정 '채널 ID'와 매핑만 하면 확장되도록 설계.

- **북마크(저장) 및 기간 맞춤 알람**
    - 크롤링된 정보 중 사용자가 '스크랩'하거나 '좋아요'를 누른 데이터만 데이터베이스(DB)에 별도 저장.

    - 공고의 신청 마감일을 파싱하여 저장하고, 스케줄러를 통해 마감 1일 전, 당일 등 지정된 시간에 자동으로 디스코드 알림을 발송.

### 2. 기술 스택 선택 이유: 디스코드 봇 + 웹

| **플랫폼**        | **담당 역할**       | **선택 이유**                                                                                                            |
| -------------- | --------------- | -------------------------------------------------------------------------------------------------------------------- |
| **디스코드 봇**<br> | **알림 및 채널별 분류** | * 카테고리/채널 생성이 자유로워 '경북대 공지', '대외활동' 등 종류별 데이터 분류 및 피드(Feed) 전송에 최적화.<br><br>* 스마트폰과 PC로 푸시 알림을 가장 빠르고 안정적으로 받을 수 있음. |
| **웹 대시보드**     | **데이터 관리 및 조회** | * 디스코드 채팅창의 휘발성 한계를 극복.<br><br>* 마음에 드는 공고를 모아서 보는 '북마크 리스트' 화면과 신청 기간을 한눈에 보는 '캘린더/스케줄러' 화면을 시각적으로 깔끔하게 구현 가능.      |

### 3. 데이터 흐름 (Data Flow)

1. **Target**: 경북대 공지사항(정적) / 통합 플랫폼(동적) 데이터 수집.
    
2. **Backend**: 크롤러가 수집한 데이터를 중복 제거 후 DB에 저장.
    
3. **Output (Discord)**: 신규 공고 발생 시 실시간으로 종류에 맞는 디스코드 채널로 푸시 알림 전송.
    
4. **Output (Web)**: 수집된 전체 데이터와 사용자가 찜한 '저장 목록' 및 '알람 일정'을 웹 화면에 동기화.
