
## 2. 무엇을 "기준(성능 지표)"으로 잡을 것인가


전략 성과는 **단일 지표가 아니라 아래 3종 세트**로 판단한다 (섹션 5의 seed 반복 시 이 지표들을 매번 계산).

| 지표                          | 용도                                         |
| --------------------------- | ------------------------------------------ |
| **누적 수익률 / CAGR**           | 기본 성과                                      |
| **Sharpe Ratio**            | 위험 대비 수익                                   |
| **K-ratio (Kestner, 1996)** | 수익곡선이 "꾸준한지"(일관성) 측정 — 반등 몇 번으로 뻥튀기된 성과 배제 |
| **MDD (최대낙폭)**              | 리스크 관리용 하한선                                |

→ 이 중 하나만 좋고 나머지가 나쁘면 "낫다"고 판단하지 않는다. **Sharpe + K-ratio 동시 개선**을 1차 기준으로 삼는다.

## 3. S&P500이 명확한 기준(Baseline)이 될 수 있는가?

**결론: 단독 기준으로는 부적합.** 시장 지수는 "베타(시장 동조)"와 "알파(전략 고유 초과수익)"가 섞여서, 전략이 잘한 건지 시장이 좋았던 건지 구분이 안 됨.

  

### 대신 3단 벤치마크 구조로 확정

  

| 레벨               | 기준                    | 목적                                                |
| ---------------- | --------------------- | ------------------------------------------------- |
| 시장 벤치마크          | KOSPI/KOSDAQ, S&P500  | "시장보다는 잘했나" 최소 기준                                 |
| **전략 벤치마크 (핵심)** | **공시 로직을 뺀 순수 차트 버전** | "공시를 더한 게 실제 도움이 됐나" 검증 — MANDU 존재 이유를 증명하는 비교 대상 |
| 랜덤 베이스라인         | 동일 유니버스 무작위 매수        | 신호 자체가 노이즈보다 나은지 최하한선                             |

→ **비교의 중심은 S&P500이 아니라 "공시 로직 있는 MANDU vs 없는 MANDU"**여야 한다.


## 4. Baseline 확정안

```

Baseline = 순수 차트 버전 (RSI + MA + MACD + 거래량, 공시 로직 제외)

```

이 버전을 먼저 고정 완성 → 이후 모든 개선(공시 결합, 팩터 추가 등)은 이 baseline 대비 개선 여부로만 판단.

## 5. Seed 변화 + 70% 판정 기준 (정교화 버전)

### Seed를 2종류로 분리

| 종류            | 방식                              | 목적                                |
| ------------- | ------------------------------- | --------------------------------- |
| **시간구간 Seed** | 전체 기간에서 랜덤 시작점/구간 N회(예: 30회) 추출 | 특정 시기(상승장 등) 과적합 여부 확인 — **더 중요** |
| **모델 Seed**   | ML 요소 있을 시 랜덤 초기화값 변경           | 모델 자체 안정성 확인                      |

### 판정 로직
 

```

N번의 독립 시행 중

신규 버전이 Baseline을 능가한 비율 ≥ 70%

AND

평균 초과수익이 거래비용+슬리피지 감안해도 유의미하게 양수

AND

Wilcoxon signed-rank test (또는 paired t-test)로 유의성 확인

```

  

### 추가 보정: Deflated Sharpe Ratio (Bailey & López de Prado, 2014)

  
seed/파라미터를 여러 번 돌릴수록 우연히 좋은 결과가 나올 확률이 올라가는 문제를 보정하는 공식. 70% 승률이 "진짜 유의미한지" 통계적으로 재검증하는 최종 필터로 사용.

  
**원칙**: 기준선(70% + 유의성 검정)은 미리 고정하고, 사이클마다 흔들지 않는다. 통과 못 하면 롤백.

## 6. Signal Blender 가중치 — 단계별 확정안

### 1단계 (즉시 구현) — 레짐 기반 정적 가중치

```python

if 추세장(ADX > 25, 정배열):

    W_chart, W_dart = 0.7, 0.3

elif 횡보장(ADX < 20):

    W_chart, W_dart = 0.4, 0.6

elif 급락장(변동성 급등):

    W_chart, W_dart = 0.3, 0.7   # 옥석가리기 비중 확대

```

  

### 2단계 (데이터 축적 후) — 롤링 성과 기반 보정

최근 20~30건 거래에서 공시/차트 신호 각각의 승률을 추적 → 1단계 가중치에 ±10~15% 미세 보정.

  

### 3단계 — 보류

역변동성 가중치는 레짐 필터와 기능 중복이라 현재는 미도입.

## 7. 학술 팩터 — 매매신호 + 검증 도구 이중 사용

  

### (A) 매매신호로 사용 (1차 스크리닝)

| 팩터       | 지표                       |
| -------- | ------------------------ |
| Value    | P/E, P/B, Earnings Yield |
| Momentum | 12-1개월 수익률, RSI          |
| Quality  | ROE, ROIC, 부채비율          |

→ 종목 유니버스를 이 팩터들로 사전 필터링 후 매매 대상 확정.

  

### (B) 사후 검증 도구로 사용 (알파 증명)

```

MANDU_수익률 = α + β1×Market + β2×SMB + β3×HML + β4×UMD + ε

```

- **α가 유의미하게 양수** → 공시 로직이 팩터로 설명 안 되는 진짜 초과수익을 만든다는 근거

- **α ≈ 0, β만 유의미** → MANDU가 사실 알려진 팩터(주로 모멘텀)를 재발견한 것뿐 → 공시 로직 재검토 필요

  

### 참고: 공시/텍스트 기반 팩터 (학술 근거)

- Loughran & McDonald (2011): 재무 전용 감성사전 — MANDU의 키워드 스코어링 방식과 동일 계열

- Cohen, Malloy & Nguyen (2020) *Lazy Prices*: 공시 문구 변화량(edit distance) — MANDU의 정정공시 diff 추적과 동일 발상

- Fang & Peress (2009): 뉴스량 자체도 팩터화 가능 → 향후 "공시 밀도"를 이벤트 강도 지표로 확장 검토

## 8. 실행 순서 요약

  

```

1. Baseline 확정 (순수 차트 버전 완성/고정)

2. 평가 프레임워크 구현 (N회 시간구간 seed + 70% + 통계검정 + Deflated Sharpe)

3. 팩터 기반 1차 스크리닝 모듈 구현 (Value/Momentum/Quality)

4. 1단계 가중치(레짐 기반)로 공시 로직 결합 → Baseline 대비 70% 기준 통과 확인

5. 팩터 회귀분석으로 알파 검증 (α 유의성 확인)

6. 통과 시 → 2단계 가중치(롤링 보정) 추가 → 다시 70% 기준 재검증

7. 일요일마다 1~6 반복

```
