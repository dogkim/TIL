
최근 고성능 SSD는 3D NAND 플래시의 고밀도화로 인해 데이터 신뢰성을 확보하기 위한 **Read-Retry(읽기 재시도)** 절차가 빈번하게 발생하고 있습니다. 이는 I/O 대역폭을 저하시키는 주요 원인이 됩니다. 본 글에서는 이러한 문제를 해결하기 위해 제안된 **RiF(Retry-in-Flash)** 스킴과 핵심 기술인 **ODEAR 엔진**에 대해 정리합니다.

---

## I. INTRODUCTION

현대 SSD는 높은 I/O 대역폭을 위해 여러 채널을 병렬로 운영하지만, 고밀도 3D NAND의 에러 발생률이 높아지면서 Read-Retry가 빈번해져 유효 대역폭이 크게 감소하고 있습니다. 기존 방식은 오프칩(Off-chip) 컨트롤러에서 에러를 판단한 후 재시도를 결정하므로 불필요한 데이터 전송과 지연 시간이 발생합니다.

## II. BACKGROUND

### A. Overview of NAND Flash Memory

NAND 플래시는 셀의 문턱 전압($V_{TH}$)을 통해 데이터를 저장합니다. P/E 사이클이 반복됨에 따라 절연층이 손상되어 전하 누설이 발생하고, 이로 인해 $V_{TH}$ 분포가 변형되면서 RBER(Raw Bit Error Rate)이 증가합니다.

### B. Error Correction in SSDs (LDPC)

에러를 교정하기 위해 **LDPC(Low-Density Parity-Check)** 코드가 널리 사용됩니다.

- **작동 원리**: 패리티 체크 행렬 $H$를 통해 신드롬 벡터 $S$를 계산하며, 에러가 없으면 신드롬 비트의 합(Weight)은 0이 됩니다.
    
- **한계**: RBER이 ECC의 정정 능력을 초과하면 디코딩에 실패하며, 이 경우 읽기 전압($V^{Ri}_{REF}$)을 변경하여 다시 읽는 Read-Retry를 수행합니다.
    
- **지연 시간 공식**: $t_{READ} = (t_R + t_{DMA} + t_{ECC}) \times (N_{RR} + 1)$
    
    - $N_{RR}$: 읽기 재시도 횟수
        
    - $t_R$: 낸드 읽기 시간
        
    - $t_{DMA}$: 데이터 이동 시간
        
    - $t_{ECC}$: ECC 디코딩 시간
        

## III. READ RETRIES IN MODERN 3D-FLASH SSDS

기존의 오프칩 기반 Read-Retry 방식은 다음과 같은 세 가지 효율성 저하 요소를 갖습니다.

1. **결정 지연**: 오프칩 ECC 엔진이 재시도 여부를 결정하므로, 데이터가 컨트롤러로 전송되어 디코딩될 때까지 재시도 필요성을 알 수 없습니다.
    
2. **대역폭 낭비**: 복구가 불가능한 페이지도 일단 컨트롤러로 전송되어야 하므로 유효 채널 대역폭이 저하됩니다.
    
3. **디코딩 지연**: 에러가 많은 페이지일수록 $t_{ECC}$가 길어지며, 이 동안 채널은 유휴 상태가 되어 효율이 떨어집니다.

## IV. DESIGN OF RIF SCHEME

RiF 스킴은 **ODEAR(On-Die Early-Retry) 엔진**을 플래시 다이 내부에 구현하여, 에러 정정 전 단계에서 재시도 여부를 미리 예측합니다.

### A. Overview of RiF Scheme

감지된 페이지가 오프칩 ECC에 의해 복구 불가능할지 예측하고, 필요시 즉시 전압을 조정하여 다시 읽습니다.

**ODEAR 엔진의 작동 순서**:

1. **RP (Read Preview)**: 페이지 버퍼의 데이터를 가볍게 훑어 에러 수준을 예측합니다.
    
2. **Retry 판단**: 에러가 적으면 즉시 전송(Ready), 많으면 재시도 단계로 진입합니다.
    
3. **RVS (Read Voltage Selection)**: 최적의 읽기 전압을 선택하고 컨트롤러에 비준비 상태를 알립니다.
    
4. **재시도 수행**: 조정된 전압으로 다시 읽은 후 깨끗한 데이터를 전송합니다.
    

### B. Read-Retry Prediction (RP Module)

RP 모듈은 LDPC 디코딩을 직접 수행하는 대신, 신드롬 웨이트(Syndrome Weight)와 RBER 사이의 상관관계를 이용합니다.

- **작동 방식**:
    
    1. 페이지 버퍼에서 데이터를 128bit씩 읽어 Segment Reg에 저장합니다.
        
    2. XOR 연산을 통해 신드롬 비트를 생성하고 1의 개수를 카운트(AC)합니다.
        
    3. 합산된 신드롬 웨이트가 설정된 기준값($P_s$)을 넘으면 재시도를 결정합니다.
        
- **최적화**:
    
    - **Chunk-based Prediction**: 페이지 내 에러 분포가 균일하다는 점을 이용해 일부(4-KiB)만 검사하여 지연 시간을 줄입니다.
        
    - **Syndrome Pruning**: 중복된 연산을 생략하여 하드웨어 부하를 최소화합니다.

## 결론

RiF 스킴은 불필요한 오프칩 데이터 전송을 차단함으로써 현대 3D NAND SSD의 I/O 성능을 크게 향상시킵니다. 실험 결과, 2K P/E 사이클 환경에서 기존 기술 대비 평균 72.1%의 대역폭 향상을 보였으며, 전력 및 면적 오버헤드는 무시할 수 있는 수준으로 나타났습니다.
