## 문제 복잡도의 두 종류

- **알고리즘 복잡도(algorithmic complexity)**: 특정 알고리즘 하나가 문제를 푸는 데 걸리는 비용
- **문제 복잡도(problem complexity)**: 그 문제를 푸는 **가장 빠른** 알고리즘의 복잡도 (예: 정렬된 배열 탐색의 문제 복잡도는 $O(\log n)$)

**계산 복잡도 이론(computational complexity)**은 문제들을 "얼마나 어려운가"에 따라 분류하는 이론이다.

## 결정 문제(Decision Problem) vs 최적화 문제(Optimization Problem)

- **결정 문제**: 입력에 대해 예/아니오로만 답하는 문제
- **최적화 문제**: "가장 좋은" 값을 갖는 해를 찾는 문제 — 항상 결정 문제로 바꿔 쓸 수 있음
  - 예: "$u$에서 $v$까지 가장 적은 간선 수의 경로를 찾아라" → "$u$에서 $v$까지 간선 수 $k$ 이하인 경로가 존재하는가?"

결정 문제가 최적화 문제보다 **쉽거나 같다** — 결정 문제 버전이 NP-complete임을 보이면 최적화 버전은 최소한 그만큼 어렵다는 뜻이 되므로, NP-완전성 이론은 주로 결정 문제를 다룬다.

## Class P

**다항 시간 알고리즘**: worst-case 실행시간이 어떤 상수 $k$에 대해 $O(n^k)$인 알고리즘. $O(n^2)$, $O(n^3)$, $O(1)$, $O(n\log n)$ 등은 다항 시간, $O(2^n)$, $O(n^n)$, $O(n!)$ 등은 비다항 시간.

**Class P** = 다항 시간에 풀 수 있는 (결정) 문제들의 집합. P에 속하는 문제를 **tractable(다루기 쉬운)**, 그렇지 않으면 **intractable(다루기 어려운) 또는 unsolvable(풀 수 없는)**이라 부른다.

주의: 다항 시간이라고 항상 실용적인 것은 아니다 — $n^{1{,}000{,}000}$은 이론상 tractable이지만 실제로는 불가능하고, $n^{\log\log\log n}$은 이론상 intractable이지만 실제로는 거의 선형에 가까워 쉽다.

**풀 수조차 없는 문제의 예 — Halting Problem**: 임의의 알고리즘과 그 입력이 주어졌을 때, 그 알고리즘이 (무한 루프에 빠지지 않고) 언젠가 멈추는지 판정하는 문제. 튜링이 1930년대에 이 문제가 **어떤 알고리즘으로도 풀 수 없음**을 증명했다.

## Class NP

문제를 두 단계로 나눠 생각한다.

1. **추측(guessing) 단계**: 정답 후보(certificate, 인증서)를 하나 생성 — 이 단계는 다항 시간이 아니어도 됨
2. **검증(verification) 단계**: 인증서와 문제 인스턴스를 받아, 그 인증서가 실제 해가 맞는지 확인 — 이 단계는 **반드시 다항 시간**

이런 절차(Nondeterministic Polynomial, NP 알고리즘)로 풀 수 있는 문제들의 집합이 **Class NP**다. 즉 NP는 "정답 인증서가 주어졌을 때 그것이 옳은지 다항 시간에 검증할 수 있는" 문제들의 집합이다 — **"NP"가 "non-polynomial"을 뜻하는 것이 아님**에 주의.

**예**: 어떤 정점 순열 $\langle v_1, \dots, v_{|V|}\rangle$이 해밀턴 사이클인지 확인하는 것은 순서대로 인접성만 훑으면 되므로 다항 시간에 검증 가능 → 해밀턴 사이클 존재 여부는 NP.

## P와 NP의 관계

- $P \subseteq NP$: 다항 시간에 풀 수 있으면, 그 해를 그냥 다항 시간에 다시 계산해서 확인하면 되므로 자명하게 검증도 다항 시간
- **$P = NP$인가?**는 컴퓨터 과학의 가장 큰 미해결 문제 — "정답을 확인하기 쉬우면, 정답을 찾는 것도 항상 쉬운가?"라는 질문과 같음
- 대부분의 학자들은 $P \ne NP$라고 믿지만 아직 증명되지 않았다 (Clay Mathematics Institute가 이 문제에 100만 달러의 상금을 걸었을 정도)

## Reduction (리덕션, 환원)

문제 $A$가 문제 $B$보다 "쉽다"($A \le B$)는 것을, "$B$를 푸는 알고리즘을 이용해 $A$도 풀 수 있다"로 정의한다. 아이디어는 $A$의 입력을 $B$의 입력으로 변환하는 함수 $f$를 만드는 것.

**다항 리덕션(polynomial reduction)**: $A \le_p B$란, $A$의 입력을 $B$의 입력으로 **다항 시간에** 바꾸는 함수 $f$가 존재하고 $A(i) = \text{YES} \iff B(f(i)) = \text{YES}$가 성립하는 것.

**예시**: $A$ = "불리언 집합에서 하나라도 TRUE인가?", $B$ = "정수 집합의 합이 양수인가?" — $x_i = \text{TRUE}$이면 $y_i=1$, 아니면 $y_i=0$으로 변환하면 $A \le_p B$.

**리덕션의 함의**

- $A \le_p B$이고 $B \in P$이면 $A \in P$ (B를 풀 수 있으니 A도 그 앞뒤로 변환만 붙이면 다항 시간에 풀림)
- $A \le_p B$이고 $A \notin P$이면 $B \notin P$ (대우 명제 — B가 P라면 A도 P여야 하는데 아니므로)

## NP-hard와 NP-complete (정의)

문제 $B$가 **NP-complete**이려면 다음 둘을 만족해야 한다.

1. $B \in NP$
2. 모든 $A \in NP$에 대해 $A \le_p B$ (NP의 모든 문제가 $B$로 다항 환원됨)

조건 2만 만족하면 **NP-hard**라 부른다. 즉 NP-complete는 "NP에 속하면서 NP-hard인" 문제들이고, NP-hard는 NP-complete보다 더 넓은 범위(NP에 속하지 않는 문제도 포함 가능)를 가리킨다.

**실전에서 NP-hard를 증명하는 방법**: "모든 NP 문제가 $A$로 환원됨"을 직접 보이는 것은 매우 어렵다(알려진, 그리고 알려지지 않은 모든 NP 문제를 다 포함해야 하므로). 대신 다음 정리를 이용한다.

> **정리**: 이미 NP-hard로 알려진 문제 $C$에 대해 $C \le_p A$이면, $A$도 NP-hard다.
>
> **증명**: $C$가 NP-hard이므로 정의에 의해 모든 NP 문제 $L$에 대해 $L \le_p C$. $C \le_p A$이므로 $L \le_p C \le_p A$, 즉 $L \le_p A$. 리덕션은 추이적(transitive)이므로 성립.

이 정리 덕분에, 이미 NP-hard로 알려진 문제 **하나만** $A$로 환원하면 충분하다. 단, 이 방법을 쓰려면 애초에 NP-hard로 알려진 "첫 문제"가 있어야 한다 — 이것이 바로 **Cook-Levin 정리**(1971)이며, SAT이 NP-hard임을 처음으로 증명했다. 이후 수많은 연구자들이 SAT으로부터(직접 또는 간접적으로) 환원해 다른 문제들의 NP-완전성을 연쇄적으로 증명해왔다.

**$P = NP$? 다시 보기**: 어떤 NP-complete 문제 하나라도 다항 시간 알고리즘이 발견되면, 그 문제로 모든 NP 문제가 환원되므로 $P = NP$가 증명된다. 아직 그런 알고리즘은 발견된 적이 없다.

## SAT과 CNF

**충족가능성 문제(SAT, Satisfiability)**: 논리식 $\Phi$가 주어졌을 때, 변수 $x_i$에 값(참/거짓)을 대입해 $\Phi$를 참으로 만들 수 있는지 판정. SAT은 **최초로 NP-complete임이 증명된 문제**다(Cook-Levin, 1971).

**CNF(Conjunctive Normal Form, 논리곱 표준형)**: 절(clause)들의 "AND"로 이뤄지고, 각 절은 리터럴(변수 또는 그 부정)들의 "OR"로만 이뤄진 형태. 예: $\Phi = (x_1 \lor x_2) \land (x_1 \lor \lnot x_2) \land (\lnot x_1 \lor \lnot x_2)$

**3-CNF-SAT**: 각 절이 정확히 3개의 서로 다른 리터럴을 갖는 CNF의 특수한 경우. **3-CNF-SAT은 NP-complete**이지만, 흥미롭게도 **2-CNF-SAT은 P**에 속한다 — 절 하나에 리터럴이 몇 개인지가 문제의 난이도를 가른다.

## P와 NP-complete 문제 예시 비교

겉보기에 비슷해 보이는 문제라도 한쪽은 P, 다른 쪽은 NP-complete인 경우가 흔하다.

| 문제 | 설명 | 복잡도 |
|---|---|---|
| 최단 경로 (Shortest Path) | 시작점에서 다른 모든 정점까지 가장 짧은 경로 | P — $O(VE)$ (Dijkstra/Bellman-Ford) |
| 최장 단순 경로 (Longest Simple Path) | 시작점에서 다른 모든 정점까지 가장 긴 경로 | **NP-complete** |
| 오일러 투어 (Euler Tour) | 모든 간선을 정확히 한 번씩 지나는 사이클 (정점은 중복 방문 가능) | P — $O(E)$ |
| 해밀턴 경로/사이클 (Hamiltonian Path) | 모든 정점을 정확히 한 번씩 지나는 사이클 | **NP-complete** |
| 외판원 문제 (TSP, 결정판) | 가중치 합 $k$ 이하인 해밀턴 사이클이 존재하는가 | **NP-complete** (최적화 버전은 NP-hard) |

## NP-완전성 이론의 실용적 의미

- 어떤 문제를 NP-complete라고 증명하는 것은, 그 문제에 다항 시간 알고리즘이 존재하지 않을 가능성이 높다는 **강력한 증거**를 제시하는 것이다(존재를 증명하는 것은 아니다 — $P \ne NP$가 미증명이므로).
- 실용적으로, NP-완전성 증명은 "더 빠른 정확한 알고리즘을 찾으려는 시도를 그만둬도 된다"는 **License**로 받아들여진다. 대신:
  - **휴리스틱**을 사용해 흔한 경우들만 잘 푼다
  - **근사 알고리즘**으로 정답에 가까운 값을 증명 가능한 오차 범위 내에서 구한다
  - 입력이 작다면 **지수 시간 알고리즘**으로 정확히 푼다
