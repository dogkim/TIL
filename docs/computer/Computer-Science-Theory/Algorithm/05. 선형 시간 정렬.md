## 비교 기반 정렬의 하한

비교(comparison)만으로 정렬하는 모든 알고리즘은 **Decision Tree**로 모델링할 수 있다 — 각 내부 노드가 하나의 비교, 각 리프가 하나의 가능한 정렬 결과(순열).

- $n$개 원소의 가능한 순열은 $n!$개이므로, decision tree는 최소 $n!$개의 리프를 가져야 함
- 높이 $h$인 이진트리의 리프는 최대 $2^h$개이므로 $2^h \ge n! \Rightarrow h \ge \log(n!)$
- **스털링 근사(Stirling's approximation)**: $n! \approx \sqrt{2\pi n}(n/e)^n$ 이므로 $\log(n!) = \Theta(n\log n)$

**결론**: 비교 기반 정렬의 worst-case 시간복잡도는 **$\Omega(n\log n)$이 하한** — merge sort/heap sort가 이 하한에 도달하는 최적 알고리즘.

이 하한을 깨려면 비교가 아닌 다른 정보(원소의 값 자체)를 이용해야 함 → 아래의 선형시간 정렬들.

## Counting Sort

원소의 값이 $0 \sim k$ 범위의 정수라는 사실을 이용.

1. 카운트 배열 $C$에 각 값의 등장 횟수를 기록
2. $C$를 누적합으로 변환 (각 값이 몇 번째 위치까지 채워지는지)
3. 입력 배열을 뒤에서부터 순회하며 $C$를 참조해 출력 위치를 결정하고 $C$ 값을 하나씩 감소 (뒤에서부터 순회해야 **stable**)

**Time**: $\Theta(n + k)$ — $k = O(n)$이면 $\Theta(n)$

## Radix Sort

여러 자리를 갖는 숫자를, **자릿수 단위**로 counting sort 등 stable한 정렬을 반복 적용 (최하위 자리부터 최상위 자리 순으로 진행).

- $d$자리 숫자, 각 자리가 $0 \sim k$ 범위라면 자리마다 counting sort를 $d$번 수행
- **Time**: $\Theta(d(n+k))$

각 단계에서 반드시 **stable sort**를 사용해야 이전 자리의 정렬 순서가 깨지지 않음.

## Bucket Sort

입력이 $[0, 1)$ 구간에 **균등하게(uniformly)** 분포되어 있다는 가정 하에 동작.

1. $n$개의 버킷을 만들고, 각 원소를 값의 크기에 비례한 버킷에 분배
2. 각 버킷 내부를 (원소 수가 적으므로) insertion sort 등으로 정렬
3. 버킷을 순서대로 이어 붙임

**Time**: $T(n) = O(n) + \sum_{i=0}^{n-1} O(n_i^2)$ ($n_i$는 $i$번째 버킷에 들어간 원소 개수)
- 균등 분포 가정 하에 $E[n_i^2] = O(1)$이므로 기댓값은 $O(n)$
