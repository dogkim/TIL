## 알고리즘 평가 기준

정확성(correctness)을 증명한 이후에는, 다음 지표들로 그 알고리즘이 얼마나 "좋은" 알고리즘인지 판단할 수 있다.

- **효율성(Efficiency)**: 얼마나 적은 메모리로 빠르게 결과를 내는지 — 시간 복잡도와 공간 복잡도로 나뉜다
- **단순성(Simplicity)**: 알고리즘이 얼마나 이해하기 쉽고 구현하기 쉬운지
- **일반성(Generality)**: 다양한 입력에 대해 일관된 성능을 보이는지
- **최적성(Optimality)**: 이론적으로 존재할 수 있는 가장 낮은 비용의 알고리즘인지

이 중 시간 효율성을 기술하는 표준적인 방법이 **점근적 분석**이다.

## 점근적 분석 (Asymptotic Analysis)

입력 크기 $n$이 무한히 커짐에 따라($n \to \infty$), 알고리즘이 소모하는 시간이나 자원의 증가율(growth rate)을 분석해 효율성과 확장성을 평가하는 방법.

두 함수 $f(n)$, $g(n)$이 있을 때:
$$\lim_{n \to \infty} \frac{f(n)}{g(n)} = 1$$
이면 $f(n) \sim g(n)$이라 쓰고, "$n$이 충분히 클 때 두 함수의 값이 사실상 같은 비율로 자란다"는 뜻이다. 정확한 계수나 저차항은 무시하고 **증가율만** 비교하는 것이 점근적 분석의 핵심이다.

## Big-O 표기법

$T(n)$이 알고리즘의 실제 실행 시간, $g(n)$이 비교 기준 함수일 때:

$$O(g(n)) = \{\,T(n) \mid \exists\, c > 0,\ n_0 > 0 \text{ s.t. } \forall n \ge n_0,\ T(n) \le c \cdot g(n)\,\}$$

풀어 쓰면: 어떤 양의 상수 $c$와 $n_0$가 존재해서, $n_0$보다 크거나 같은 모든 $n$에 대해 $T(n) \le c \cdot g(n)$이 성립하면 $T(n) = O(g(n))$이다.

Big-O 표기법은 알고리즘 실행 시간의 **상한(upper bound)**을 나타낸다 — "이 알고리즘은 아무리 늦어도 이 정도 속도로는 끝난다"는 보장.

### $T(n) = O(g(n))$임을 증명하는 방법

정의에 맞는 $c$와 $n_0$가 존재함을 직접 제시한다.

**예시**: $T(n) = n$, $g(n) = n\log_2 n$일 때 $T(n) = O(g(n))$임을 보이자.

- $c = 1$, $n_0 = 2$로 두자
- $n \ge n_0 = 2$이면 $n$은 양수이고, $\log_2 n \ge 1$이므로 $n \le n \cdot \log_2 n = c \cdot g(n)$이 성립
- 따라서 $T(n) = O(n\log n)$

### $T(n) \ne O(g(n))$임을 증명하는 방법

$T(n) = O(g(n))$이라고 가정한 뒤, 모순을 이끌어내 반증한다(귀류법).

**예시**: $T(n) = n^2$, $g(n) = n$일 때 $T(n) \ne O(g(n))$임을 보이자.

- **가정**: $T(n) = O(g(n))$이라고 가정 — 즉, 모든 $n \ge n_0$에 대해 $n^2 \le cn$을 만족하는 양의 상수 $c$, $n_0$가 존재한다고 가정
- **반례 구성**: $n = \max\{c, n_0\} + 1$인 $n$을 생각하자. 이 $n$은 $n \ge n_0$이면서 동시에 $n > c$를 만족
- $n > c$이므로 양변에 $n$을 곱하면 $n^2 > cn$
- 즉 $n \ge n_0$인 어떤 $n$에서 $n^2 > cn$이 성립해, 가정("모든 $n \ge n_0$에서 $n^2 \le cn$")과 모순
- 따라서 그런 $c$, $n_0$는 존재하지 않고, $T(n) \ne O(g(n))$
