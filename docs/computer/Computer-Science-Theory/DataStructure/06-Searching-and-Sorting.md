## 1. 탐색 (Searching)

### Linear (Iterative) Search
배열을 처음부터 끝까지 순서대로 훑으며 비교.
- 시간 복잡도: $O(n)$ (평균적으로 $(n+1)/2$번 비교)

### Binary Search
정렬된 배열에서, 중간 값과 비교해 탐색 범위를 절반씩 줄여나감.
- 시간 복잡도: $O(\log n)$
- 전제조건: 배열이 미리 **정렬**되어 있어야 함

## 2. 정렬 (Sorting)

### Insertion Sort
앞에서부터 정렬된 부분을 유지하며, 새 원소를 그 안의 알맞은 위치에 삽입.
- **Worst case**: $O(n^2)$ (완전히 내림차순으로 정렬된 입력)
- **Best case**: $O(n)$ (이미 오름차순으로 정렬된 입력 — 비교만 하고 이동이 거의 없음)
- 작은 크기의 배열이나 거의 정렬된 배열에 유리

### Quick Sort
pivot을 기준으로 작은 값/큰 값으로 나눈 뒤 각각 재귀적으로 정렬.
- **Worst case**: 두 서브리스트의 길이가 크게 차이 나는 경우 (이미 정렬된 배열에 첫/끝 원소를 pivot으로 쓸 때 등) — $O(n^2)$
- **Optimal case**: 매번 절반씩 균등하게 나뉠 때 — $O(n\log n)$

### Merge Sort
정렬된 두 배열(또는 재귀로 쪼갠 두 부분)을 새 배열에 합쳐나가는 방식 (재귀 + 병합).
- 시간 복잡도: $O(n\log n)$ (항상 절반씩 나뉘므로 worst case에도 안정적)
- $n \le 15$ 정도로 작을 때는 오버헤드 때문에 오히려 insertion sort가 더 빠른 경우가 많음 (그래서 실전 구현은 작은 구간에서 insertion sort로 전환하는 하이브리드 방식을 씀)
- 공간 복잡도: $O(n)$ (병합에 추가 배열 필요, in-place가 아님)

### Heap Sort
Max-heap을 만든 뒤, 루트(최댓값)를 하나씩 꺼내 뒤에서부터 채워나가는 방식.
- 시간 복잡도: $O(n\log n)$
- 공간 복잡도: $O(1)$ (in-place) — merge sort와 달리 추가 배열이 필요 없음
