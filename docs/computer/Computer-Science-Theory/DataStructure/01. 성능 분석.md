## 프로그램의 평가 기준

- **공간 효율성(Space Efficiency)**: 프로그램이 실행되는 동안 메모리를 얼마나 효과적으로 사용하는가?
- **시간 효율성(Time Efficiency)**: 프로그램이 특정 작업을 수행하는 데 걸리는 시간이 적절한가?

## 프로그램 복잡도 (Program Complexity)

정확한 알고리즘의 실용성을 파악하려면, 특정 하드웨어에 의존하지 않는 **기계 독립적인 추정치**가 필요하다.

- **시간 복잡도(Time complexity)**: 알고리즘이 문제를 해결하기 위해 수행하는 기본 연산 횟수의 총합
- **공간 복잡도(Space complexity)**: 알고리즘 실행부터 종료까지 필요한 최대 메모리 공간

## 성능 평가 단계

**성능 측정(Performance measurement) — 귀납적 테스팅(A Posteriori)**: 실제 환경에서 실행 시간을 측정.

```C
#include <time.h>
clock_t start = clock();
/* 실행 코드 */
clock_t stop = clock();
double duration = (double)(stop - start) / CLOCKS_PER_SEC;
```

**성능 측정의 문제점**
1. 알고리즘을 직접 구현하고 테스트하는 과정을 거쳐야 함 (복잡한 경우 부담)
2. 하드웨어·컴파일러 등 실험 환경에 따라 결과가 가변적임
3. 실험에 사용하지 않은 데이터에 대해서는 다른 결과가 나올 수 있음

**성능 분석(Performance analysis) — 연역적 평가(A Priori)**: 프로그램을 실제로 실행하지 않고, 알고리즘의 논리적 단계를 통해 복잡도를 계산.

- **점근적 분석(Asymptotic Analysis)**: 데이터 크기 $n$이 무한대로 커질 때의 증가율을 $O$, $\Omega$, $\Theta$ 표기법으로 분석

### 점근적 표기법 (Asymptotic Notation)

데이터가 무한히 많아질 때($n \to \infty$) 함수의 상한선·하한선을 표현하는 방식.

| 표기법 | 의미 | 정의 |
|---|---|---|
| **Big-O ($O$)** — 점근적 상한, 최악의 경우 | 모든 $n \ge n_0$에서 $f(n) \le c \cdot g(n)$을 만족하는 양의 상수 $c$, $n_0$가 존재 | $f(n) = O(g(n))$ |
| **Big-Omega ($\Omega$)** — 점근적 하한, 최선의 경우 | 모든 $n \ge n_0$에서 $f(n) \ge c \cdot g(n)$을 만족하는 양의 상수 $c$, $n_0$가 존재 | $f(n) = \Omega(g(n))$ |
| **Big-Theta ($\Theta$)** — 점근적 상하한, 정확한 증가율 | 모든 $n \ge n_0$에서 $c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$을 만족하는 양의 상수 $c_1, c_2, n_0$가 존재 | $f(n) = \Theta(g(n))$ |

**예시**: $f(n) = 3n + 5$라면, $n \ge 5$일 때 $3n + 5 \le 4n$이 성립하므로 $f(n) = O(n)$.

### 예시 — 선형 탐색(Linear Search)

```c
#include <stdio.h>
LinearSearch(int a[], int n, int val) {
    for(int i = 0; i < n; i++){ // 1: n + 1 회
        if(a[i] == val){ // 2: n회
            return i;
        }
    }
    return -1;
}
```

**Big-O (최악의 경우)**: 찾으려는 값이 배열에 없는 경우

| 연산 항목(Line) | 실행 횟수 | 비고 |
|---|---|---|
| `int i = 0` | 1 | 초기화 1회 |
| `i < n` | $n+1$ | $n$번 성공 후, 마지막 실패 비교까지 포함 |
| `a[i] == val` | $n$ | 루프 내부 비교 연산 $n$회 |
| `i++` | $n$ | 루프 끝에서 증감 연산 $n$회 |
| `return -1` | 1 | 루프 종료 후 마지막에 실행 |
| **합계** | **$3n+3$** | 입력 크기 $n$에 대한 전체 연산식 |

$g(n) = n$, $c = 4$, $n_0 = 3$으로 두면 $n \ge 3$인 모든 경우에 $3n+3 \le 4n$이 성립 → $O(n)$.

**Big-$\Omega$ (최선의 경우)**: 첫 번째 인덱스에서 바로 찾는 경우

| 연산 항목 | 실행 횟수 | 비고 |
|---|---|---|
| `i = 0` (초기화) | 1회 | |
| `i < n` (조건 검사) | 1회 | 첫 번째 루프 진입 |
| `a[i] == val` (비교) | 1회 | 바로 참 발생 |
| `return i` (반환) | 1회 | 즉시 종료 |
| **합계** | **4회** | $n$의 값과 무관하게 항상 4 |

$g(n) = 1$, $c=1$, $n_0=1$로 두면 모든 $n \ge 1$에서 $4 \ge 1$이 성립 → $\Omega(1)$.

**Big-$\Theta$**: 입력 데이터의 상태(최선/최악)에 따라 실행 시간의 차이가 크므로, 선형 탐색 전체 성능을 하나의 $\Theta$로 정의할 수는 없음.

## 공간 복잡도 (Space Complexity)

고정적 부분과 가변적 부분의 합으로 구성:

$$S(P) = c + S_p(n)$$

- $S(P)$: 프로그램 $P$의 공간 요구량
- $c$: 인스턴스 특성과 무관한 고정 공간 (예: 코드 저장 공간, 단순 변수)
- $S_p(n)$: 인스턴스 특성($n$)에 따라 크기가 달라지는 가변 공간 (예: 재귀 호출 시 쌓이는 스택 프레임)
- $n$ (Instance characteristics): 인스턴스 특성 — 입출력 크기·개수 등

**예시 1** — 가변 공간 없음

```C
float abc(float a, float b, float c){
    return a+b+b*c+(a*b-c) / (a+b) + 4.00;
}
```
$a, b, c$의 크기와 무관하게 추가로 할당되는 가변 공간이 없음 → $S_{abc}(n) = 0$

**예시 2** — 재귀 호출에 따른 스택 프레임 누적

```C
float rsum(float list[], int n){
    if (n <= 0) return 0;
    return rsum(list, n-1) + list[n-1];
}
```

호출될 때마다 매개변수·복귀 주소 등을 담은 스택 프레임이 쌓이며, $n$부터 $0$까지 총 $n+1$번 호출된다.

| Type | Name | Number of bytes |
|---|---|---|
| parameter: Array pointer | `list[]` | 4 |
| parameter: Integer | `n` | 4 |
| return address (내부 처리용) | | 4 |
| **호출당 합계** | | **12** |

최악의 경우: $S_{rsum}(\text{MAX\_SIZE}) = 12 \times (\text{MAX\_SIZE} + 1)$

## 시간 복잡도(Time Complexity) 예시

입력 크기($n$)에 따라 알고리즘이 수행하는 연산 횟수를 분석.

```c
float sum(float list[], int n) {
    float s = 0; // 1: 1회
    for (int i = 0; i < n; i++){ // 2: n+1회 (마지막 조건 체크 포함)
        s += list[i]; // 3: n회 연산
    }
    return s; // 4: 1회
}
```

**합계**: $1 + (n+1) + n + 1 = 2n+3$ → 시간 복잡도 $O(n)$
