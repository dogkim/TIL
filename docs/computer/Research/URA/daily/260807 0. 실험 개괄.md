## 2. high low watermark 사용 후 latency관찰 
	1. precondition이 끝난 시점의 free line의 절반까지 low를 증가시켜보며 관찰.
		(536의 절반인 268까지. 2, 134, 268 3가지 값 관찰)
	2. high, low와 block 당 page 변화 후 관찰

앞으로 방향
1. while 들어간 수정된 코드 seq gc 돌려보고 기존과 동일한지 비교.
2. 문제 없으면 thres high low 변화후 관찰
3. low만으로 평형이 유지될시 bs를 키워서 진행
4. high low 값 변화 하면 값 뽑음

추출할 데이터 목록
1. 시간 기준 free line 변화 그래프
2. lat 그래프
3. gc 발생 횟수

변화 코드
high에 도달시 low까지 do_gc 반복 실행

```C
static void foreground_gc(struct conv_ftl *conv_ftl)

{

    if (should_gc_high(conv_ftl)) {
        NVMEV_DEBUG_VERBOSE("should_gc_high passed");
        /* perform GC here until !should_gc(conv_ftl) */
        while (should_gc(conv_ftl)) {
        // low watermark 아래로 내려갈 때까지 반복
            if (do_gc(conv_ftl, true) != 0)  
            // victim이 더 없으면 (-1 리턴) 중단
                break;
        }

    } else if (should_gc(conv_ftl)) {
        do_gc(conv_ftl, false);               
        // low watermark: opportunistic 1회만
    }
}
```
