**1. 물리적 구조 (실제 칩 안 구조)**

```
Channel (채널)
  └─ LUN (=Die, 칩 하나)
       └─ Plane (플레인)
            └─ Block (블록)
                 └─ Page (페이지) ← 실제 데이터 최소 저장 단위
```

**각 단계가 뭔지 (한 번 더 압축해서)**

- **Channel**: 컨트롤러와 칩들을 잇는 통로(도로)
- **LUN**: 그 통로에 연결된 독립 칩 하나 (병렬로 동작 가능)
- **Plane**: 칩 안의 구역
- **Block**: 지우기(erase)의 최소 단위
- **Page**: 쓰기(write)의 최소 단위 (Block 안에 여러 Page)

**2. "Line"이 뭔지 — 이게 핵심**

Line은 물리적 구조가 아니라, **여러 채널·LUN에 걸쳐서 "동시에 함께 쓰이고, 함께 지워지는 블록들의 묶음"**을 관리 편의상 부르는 논리적 단위야.

**왜 이렇게 묶어서 관리하는지**

채널이 8개, LUN이 2개면 총 16개의 병렬 유닛이 있잖아. SSD는 속도를 위해 **이 16개에 동시에 걸쳐서 데이터를 쓰는 게** 효율적

```
Line 1 = [채널0-LUN0의 블록3] + [채널0-LUN1의 블록3] + [채널1-LUN0의 블록3] + ... (16개 블록 묶음)
```

**Line**:  여러 채널·LUN에 흩어진 블록들을, 관리상 하나의 단위로 묶어서 부르는 이름.
GC도 Line 단위로 진행 — Line 하나를 통째로 정리(valid 복사 + 지우기)

**3. 우리가 실습한 1채널×1LUN에서는 왜 "Line = Block"이 되는지**

```
채널이 8개일 때: Line = 8개 채널의 블록들을 묶음 (16개, LUN까지 곱하면)
채널이 1개, LUN이 1개일 때: 묶을 대상이 하나뿐 → Line = 그냥 블록 1개 그 자체
```

병렬로 걸칠 다른 채널/LUN이 없으니까, "여러 개를 묶는다"는 Line의 원래 의미가 무색해지고, **Line 하나 = Block 하나**로 단순하게 대응
