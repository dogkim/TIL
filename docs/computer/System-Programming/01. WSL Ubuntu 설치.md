## 개요

ELEC462 시스템 프로그래밍 실습은 Ubuntu 24.04 환경을 전제로 함. Windows에서는 WSL(Windows Subsystem for Linux)을 쓰는 걸 강의에서 권장.

Windows에서 Ubuntu를 쓰는 방법은 여러 가지:
- **WSL** — Windows 안에서 리눅스 커널이 Hyper-V 기반 경량 VM으로 돌아가는 방식. 강의 권장 방법
- **가상머신(VM)** — VMware Workstation Player 등으로 통째로 가상화
- **원격 리눅스 서버** — GCP/AWS 프리티어에 SSH 접속
- **듀얼부팅**

## WSL 설치 손상 문제 해결

`wsl --list --online` 실행 시 다음 오류 발생:
```
wsl: WSL 설치가 손상된 것 같습니다
오류 코드: Wsl/CallMsi/Install/REGDB_E_CLASSNOTREG
```

`wsl.exe`는 Windows에 기본 내장되어 있어서 따로 설치한 적이 없어도 존재하는데, COM 클래스 등록이 깨져서 발생하는 문제였음. 관리자 권한 터미널에서:
```bash
wsl --update
```
실행하니 "아무 키나 눌러 복구" 프롬프트가 뜨고, 복구 진행 후 정상 버전(2.7.13)으로 업데이트되면서 해결됨.

(만약 이걸로 안 됐다면 다음 단계로 WSL 기능을 껐다 켜는 방법이 있음:
```bash
dism.exe /online /disable-feature /featurename:Microsoft-Windows-Subsystem-Linux /norestart
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
```
재부팅 후 재시도.)

## Ubuntu 24.04 설치

```bash
wsl --install -d Ubuntu-24.04
wsl --set-default Ubuntu-24.04
```

첫 실행 시 유닉스 사용자 계정(이름/비밀번호)을 새로 만들어야 함 — Windows 계정과는 무관한 별개의 리눅스 계정.

버전 확인:
```bash
cat /etc/issue
# Ubuntu 24.04.4 LTS
```

## WSL과 Windows의 관계

WSL2는 듀얼부팅과 달리, Windows가 켜진 상태에서 리눅스 커널이 Hyper-V 기반 VM으로 백그라운드에 같이 돌아가는 구조. 물리적으로는 커널과 파일시스템이 분리된 두 시스템이지만, `wsl` 명령 한 번으로 몇 초 만에 오가며 Windows 탐색기(`\\wsl$\`)에서도 리눅스 파일에 접근 가능해서 듀얼부팅보다 훨씬 통합되어 있음.

- 리눅스 파일시스템은 `.vhdx` 가상 디스크 파일 안에 통째로 들어있음 (직접 건드리면 안 되고 `wsl` 명령이나 `\\wsl$\` 경로로만 접근)
- `/mnt/c/`가 곧 Windows의 `C:\` — WSL에서 Windows 파일에 접근할 때 씀
- 실습 파일은 `/mnt/c/...`가 아니라 리눅스 홈 디렉토리(`~`, 즉 `/home/<user>`)에 두는 게 속도/권한 면에서 유리

## 실습 폴더 세팅 & VS Code 연결

```bash
cd ~
mkdir elec462
cd elec462
```

VS Code(Windows에 설치된 것) + **WSL 확장** 설치 후, WSL 셸에서:
```bash
code .
```
최초 실행 시 리눅스 쪽에 VS Code Server를 자동 설치함 (한 번만, 정상 과정). 완료되면 VS Code 좌측 하단에 `WSL: Ubuntu-24.04` 배지가 뜨는 것으로 연결 확인.

구조: Windows의 VS Code가 화면(GUI)만 담당하고, 실제 파일 읽기/터미널 실행/확장 동작은 리눅스 쪽 VS Code Server가 담당하는 방식.

## 참고: NVMeVirt는 WSL과 안 맞음

같은 시스템 프로그래밍 관련 실험이라도 [NVMeVirt](https://github.com/snu-csl/nvmevirt) 같은 커널 모듈 프로젝트는 WSL2로 돌리기 어려움:
- WSL2는 Microsoft가 자체 빌드한 특수 커널이라 `apt`로 받는 일반 커널 헤더가 없음 — 모듈을 빌드하려면 WSL2 커널 소스를 직접 받아 빌드해야 함
- 부팅 시 메모리 영역을 예약(`memmap=`)해야 하는 요구사항도 WSL2에서는 지원이 불확실
- 이런 커널 모듈 실습은 VM(VMware/VirtualBox)이나 베어메탈 리눅스에서 하는 게 안전
