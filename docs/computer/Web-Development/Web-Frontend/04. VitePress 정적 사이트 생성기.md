## VitePress란

[[03. Vite 빌드 도구|Vite]]와 [[02. Vue 프레임워크|Vue]]를 재료로 써서, "마크다운 파일을 쓰면 자동으로 사이드바·검색·다크모드가 있는 문서 사이트가 나온다"는 특정 목적에 맞게 미리 다 짜놓은 **정적 사이트 생성기(Static Site Generator)**. React 생태계의 Next.js가 React 위에 얹힌 것과 같은 구조 — Vue/Vite를 대체하는 게 아니라 재료로 삼아 만든 상위 도구다.

TypeScript(JS 위에 타입 체크를 얹음)와 "레이어를 쌓는다"는 패턴은 같지만, VitePress는 범용이 아니라 "문서 사이트 만들기"라는 목적 한정형이라는 점이 다르다.

## 마크다운이 사이트가 되는 파이프라인

1. `docs/*.md` 파일을 **markdown-it**(마크다운 파서)이 읽어 HTML로 변환하되, Vue가 이해할 수 있는 형태로 가공한다 — 그래서 마크다운 안에 `<CustomComponent />` 같은 Vue 컴포넌트도 끼워 쓸 수 있다.
2. 이렇게 만들어진 각 페이지는 내부적으로 **하나의 Vue 컴포넌트**가 된다 — 이 노트 파일도 결국 눈에 안 보이는 `.vue` 파일 취급을 받는 셈.
3. **빌드 시점에 서버 환경에서 Vue를 한 번 미리 실행**해서 완성된 정적 HTML을 미리 만들어둔다 — 이를 **SSG(Static Site Generation)**라 한다. 사용자가 처음 접속했을 때 이미 완성된 HTML을 즉시 받아볼 수 있어 빠르고, 검색엔진 최적화(SEO)에도 유리하다.
4. 브라우저에 그 정적 HTML이 로드된 뒤, Vue가 그 위에 다시 "살아있는 상태"를 입혀 클릭·반응성이 동작하게 만든다 — 이 단계를 **하이드레이션(Hydration)**이라 한다.

즉 VitePress 사이트는 처음엔 순수 정적 HTML처럼 빠르게 뜨고, 그다음 조용히 Vue가 "깨어나서" 인터랙티브해지는 2단계 과정을 거친다.

## 홈페이지 커스터마이징 방법 (TIL 개편 작업 관련)

VitePress는 이미 완성된 기본 테마(사이드바/검색/다크모드 Vue 컴포넌트)를 제공하며, 보통은 이 컴포넌트를 설정 파일과 마크다운 프론트매터로 "채워넣는" 방식으로 쓴다.

```yaml
---
layout: home
hero:
  name: "이름"
  tagline: "한 줄 소개"
features:
  - title: Computer Science
    details: 알고리즘, 자료구조...
---
```

기본 히어로+피처 카드로 부족할 때는 두 방법 중 하나로 확장한다:

- **슬롯 확장**: `docs/.vitepress/theme/index.js`에서 기본 테마를 가져와, VitePress가 열어둔 슬롯(`home-hero-before`, `home-features-after` 등)에 커스텀 컴포넌트를 끼워 넣음 — 사이드바/검색 등 나머지는 기본 테마가 그대로 처리.
- **완전 커스텀 레이아웃**: 홈페이지만 기본 테마 대신 직접 만든 `Home.vue`로 교체하고(`layout: custom-home`), 나머지 문서 페이지는 기본 테마를 그대로 유지 — 포트폴리오 느낌의 홈 + 문서 사이트 느낌의 내부 페이지를 동시에 구현할 때 쓰는 방식.
