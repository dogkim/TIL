## Vite란

Vite는 프로그래밍 언어가 아니라 **빌드 도구(build tool)**다. [[02-Vue-Framework|Vue]]로 짠 `.vue` 파일들을 브라우저가 이해할 수 있는 순수 HTML/CSS/JS로 변환·번들링해주는 인프라 역할을 한다.

- JS/TS = 요리 재료 (실제 코드)
- Vue = 요리 방식/도구 세트 (화면 구성 방법론)
- **Vite = 주방 자체** — 재료를 실제로 조리해서 손님상에 낼 수 있게 만듦

## 개발 서버가 빠른 이유

옛날 빌드 도구(Webpack 등)는 개발 서버를 켤 때 프로젝트 전체를 미리 다 번들링해서 하나로 뭉쳐놨다 — 파일이 많아질수록 시작이 느려짐. Vite는 다르게 접근한다.

- **개발 중**: 브라우저가 원래 지원하는 **ES 모듈(ESM)**을 그대로 활용해서, 브라우저가 필요한 파일을 요청할 때마다 그 파일 하나만 즉석에서 변환해서 준다(번들링 없음). 외부 라이브러리(`node_modules`)는 **esbuild**(Go로 만들어져 극도로 빠른 변환기)로 미리 한 번만 압축해둔다. 그 결과 파일이 수천 개여도 서버 기동에 1초도 안 걸림.
- **배포용 빌드**(`npm run build`): 반대로 **Rollup**을 써서 전체를 하나로 압축·최적화된 번들로 만든다 — 배포 시엔 속도보다 최종 결과물 크기/성능이 중요하기 때문.

## HMR (Hot Module Replacement)

코드를 저장하면 페이지 전체를 새로고침하는 게 아니라, **바뀐 컴포넌트 하나만** 쏙 빼서 교체한다. 그래서 폼에 입력하던 값 같은 상태가 유지된 채로 화면만 바뀌는 게 가능하다 — [[../URA/results/01 NVMeV GC 기초 검증 실험|URA 실험]] 코드처럼 값을 바꿔가며 반복 테스트할 때의 편의성과 비슷한 이점을 프론트엔드 개발에서 제공한다고 보면 된다.

## 요약: 컴파일 파이프라인에서의 위치

```
.vue 파일 작성 → Vite(@vitejs/plugin-vue)가 쪼개고 변환 → 순수 JS/CSS 결과물 → 브라우저 실행
```
