## 전체 그림: 웹은 왜 이렇게 여러 겹으로 쌓여있나

웹 프론트엔드 기술은 "필요에 따라 그 아래 것을 재료로 삼아 새로운 도구를 얹는" 방식으로 계속 층이 쌓여왔다. TIL 사이트(VitePress)를 예로 들면 이렇게 4단계다.

| 층 | 이름 | 역할 | 이 자체로 실행 가능한가? |
|---|---|---|---|
| 1 | **JavaScript** | 웹의 유일한 프로그래밍 언어(로직/동작) | ✅ 브라우저가 직접 실행 |
| 2 | **Vue** | JS로 화면을 컴포넌트 단위로 만드는 UI 프레임워크 | ❌ 빌드해야 실행 가능 |
| 3 | **Vite** | Vue 코드를 브라우저가 이해할 형태로 변환/번들링하는 빌드 도구 | (도구 자체는 Node.js에서 실행) |
| 4 | **VitePress** | Vite+Vue를 재료로 "마크다운 → 문서 사이트" 용도에 특화시킨 정적 사이트 생성기 | (내부적으로 1~3 전부 사용) |

## 언어 3형제와 프로그래밍 언어의 차이

HTML(구조)·CSS(스타일)는 마크업/스타일 언어일 뿐 로직이 없고, **JavaScript만이 Java·Python과 동급인 진짜 프로그래밍 언어**다(변수, 함수, 조건문, 반복문을 갖춤). "버튼이 어떻게 생겼는지"는 HTML/CSS가, "버튼을 클릭하면 무슨 일이 일어나는지"는 JS가 담당한다.

## 같은 급 프레임워크들

Vue와 같은 레벨(JS 기반 UI 프레임워크)에 있는 경쟁자들:

| 프레임워크 | 만든 곳 | 위에 얹힌 메타 프레임워크 |
|---|---|---|
| React | Meta | Next.js, Docusaurus |
| Vue | Evan You(개인) | Nuxt, **VitePress** |
| Angular | Google | (자체 완결형이라 메타프레임워크 개념이 약함) |
| Svelte | Rich Harris(개인) | SvelteKit |

TypeScript도 같은 "레이어를 쌓는" 패턴이지만 대상이 다르다 — TypeScript는 **JS 언어 자체**에 타입 체크를 더하는 것이고, VitePress는 **Vue라는 프레임워크**를 문서 사이트라는 특정 용도에 특화시킨 것이다.
