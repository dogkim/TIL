## HTML/CSS와의 근본적인 차이

- **HTML**: 구조를 정의하는 마크업 언어 (로직 없음)
- **CSS**: 스타일을 정의하는 스타일 언어 (로직 없음)
- **JavaScript**: 변수·함수·조건문·반복문을 갖춘 **진짜 프로그래밍 언어** — Java, Python과 동급

```javascript
let count = 0;
function increment() {
    count = count + 1;
    if (count > 10) {
        console.log("많이 눌렀네요");
    }
}
```

HTML/CSS는 "버튼이 어떻게 생겼는지"만 정하고, "클릭하면 숫자가 올라간다"는 동작은 JS만 할 수 있다.

## 브라우저에서 어떻게 실행되나

브라우저 안에는 **JS 엔진**(Chrome은 V8, Safari는 JavaScriptCore)이 내장돼 있어서, JS 코드를 한 줄씩 해석하며 즉시 실행한다(인터프리터 방식). 다만 자주 실행되는 코드는 내부적으로 기계어로 컴파일해서 최적화한다(JIT, Just-In-Time compilation) — [[../Java/01. Java 소개|Java]]가 "미리 컴파일 → 바이트코드 → JVM 실행"의 3단계를 거치는 것과 달리, JS는 브라우저가 텍스트 코드를 그 자리에서 바로 실행한다는 점이 다르다.

## 싱글 스레드 + 이벤트 루프

JS는 한 번에 한 작업만 처리하는 **싱글 스레드**다. 하지만 `setTimeout`, 클릭 이벤트, 네트워크 요청같이 시간이 걸리는 작업은 **대기열(큐)**에 쌓아뒀다가, 현재 실행 중인 코드가 끝나면 순서대로 꺼내서 처리한다 — 이 매커니즘을 **이벤트 루프**라 하고, 이 덕분에 JS는 "느린 작업을 기다리는 동안 다른 일을 계속 처리"하는 비동기(async) 프로그래밍이 가능하다.

## TypeScript와의 관계

TypeScript는 JS 위에 **타입 체크** 기능을 얹은 것 — 브라우저는 TypeScript를 이해하지 못하므로, 결국 컴파일 과정을 거쳐 순수 JavaScript로 변환된 뒤에야 실행된다. "기반 기술 위에 특정 기능을 얹고, 결국 원래 형태로 변환되어 실행된다"는 이 패턴은 뒤에 나올 Vue의 `.vue` 파일이 컴파일되는 방식과 똑같다.
