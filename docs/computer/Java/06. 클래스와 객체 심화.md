## 정확한 값 vs 일관된 값

**일관성(consistent) 있는 데이터**: 객체가 항상 유효한 범위 안의 값을 유지하는 것 (예: `minute`는 항상 0~59). **정확성(correct)**은 그 값이 실제 상황과 일치하는지의 문제 — 정확한 값은 항상 일관되지만, 일관된 값이 항상 정확한 것은 아님(예: 실제로는 17분인데 19분으로 설정해도 19는 여전히 유효 범위 안이므로 '일관'되지만 '정확'하지는 않음).

좋은 클래스 설계는 생성 시점부터 일관된 상태(예: 기본값 0)로 시작하고, `set` 메서드가 잘못된(비일관적인) 값을 거부하도록 만들어 **객체가 항상 일관된 데이터를 유지**하도록 함.

## 접근 제어자

- `public`: 클래스의 클라이언트에게 제공하는 서비스(**공개 인터페이스**) — 클라이언트는 클래스가 작업을 *어떻게* 수행하는지 알 필요가 없음
- `private`: 클래스 외부에서 접근 불가 — 구현 세부사항을 감춤
- `protected`: (9장에서 다룸) `public`과 `private`의 중간 — 같은 클래스, 서브클래스, 같은 패키지의 다른 클래스에서 접근 가능

## this 참조

모든 객체는 `this` 키워드로 **자기 자신에 대한 참조**에 접근할 수 있음. `static`이 아닌 메서드가 호출되면, 그 메서드 본문은 암묵적으로 `this`를 사용해 그 객체의 인스턴스 변수·다른 메서드를 참조함 — 명시적으로 `this.필드명`처럼 쓸 수도 있음(같은 이름의 매개변수와 필드를 구분할 때 특히 유용).

```java
public void setHour(int hour) {
    this.hour = hour;   // 매개변수 hour와 필드 this.hour 구분
}
```

## 생성자 오버로딩

여러 개의 생성자를 시그니처(매개변수 개수·타입·순서)만 다르게 선언해 객체를 다양한 방식으로 초기화할 수 있음.

```java
public Time2() { this(0, 0, 0); }                 // 무인자 생성자
public Time2(int h) { this(h, 0, 0); }
public Time2(int h, int m) { this(h, m, 0); }
public Time2(int h, int m, int s) { setTime(h, m, s); }
```

생성자 본문의 **첫 문장**에서 `this(...)`를 호출하면 같은 클래스의 다른 생성자를 호출함 — 초기화 코드를 중복 작성하지 않고 재사용하는 흔한 패턴. (생성자를 하나라도 직접 선언하면, 컴파일러는 기본 생성자를 자동으로 만들어주지 않음.)

## 합성 (Composition, has-a 관계)

한 클래스가 다른 클래스의 객체를 멤버(필드)로 참조하는 능력 — "A는 B를 가진다(has-a)" 관계. (상속의 "A는 B이다(is-a)" 관계와 대조됨, [[07. 상속]] 참고)

```java
public class Employee {
    private Date birthDate;   // Employee has-a Date
}
```

## static 멤버와 final 인스턴스 변수

- `static` 필드: 클래스의 모든 객체가 공유하는 단일 사본 (예: 생성된 객체 수를 세는 카운터)
- `final` 인스턴스 변수: 생성자에서 한 번 초기화되면 이후 변경 불가능한 필드 (상수와 달리 객체마다 다른 값을 가질 수 있음)

## enum 타입

관련된 상수들의 집합을 안전하게 정의하는 타입.

```java
public enum Day { MONDAY, TUESDAY, WEDNESDAY /* ... */ }

Day today = Day.MONDAY;
```

## 패키지로 클래스 조직화

관련된 클래스들을 **패키지**로 묶어 대규모 애플리케이션을 관리하고 재사용을 촉진 — 디렉터리 구조와 대응됨 (`package com.example.myapp;` 선언 + 해당 디렉터리 경로).
