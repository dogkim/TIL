## java.base 모듈

Java 9부터 표준 라이브러리가 **모듈(module)** 단위로 나뉘었고, `java.base`는 **모든 모듈이 공통으로 의존하는 기본 모듈**이다.

| 패키지 | 용도 |
|---|---|
| `java.lang` | 자바 언어의 기본 클래스 — **import 없이 사용 가능** (`String`, `System`, `Integer`, `Exception` 등) |
| `java.util` | 컬렉션 등 자료구조 클래스 ([[13. 제네릭 컬렉션\|13장]] 참고), `Scanner` |
| `java.text` | 날짜·숫자를 원하는 문자열 형태로 포맷 |
| `java.time` | 날짜·시간 연산 |
| `java.io` | 입출력 스트림 ([[12. 파일, 스트림과 직렬화\|12장]] 참고) |
| `java.net` | 네트워크 통신 |
| `java.nio` | Buffer 기반의 새로운 입출력 |

`java.lang` 패키지의 클래스만 `import` 없이 바로 쓸 수 있는 이유가 바로 이것 — 나머지 패키지(`java.util.Scanner` 등)는 항상 명시적으로 import해야 한다.

## Object 클래스: 모든 클래스의 최상위 클래스

`extends`로 다른 클래스를 상속하지 않으면 모든 클래스는 암시적으로 `java.lang.Object`를 상속한다 ([[07. 상속|7장 상속]] 참고).

| Object 메서드 | 용도 |
|---|---|
| `boolean equals(Object obj)` | 객체의 **주소**를 비교(`==`와 동일) — 재정의하지 않으면 참조 비교 |
| `int hashCode()` | 객체의 해시코드(기본은 메모리 주소 기반) 리턴 |
| `String toString()` | 객체 정보를 문자열로 리턴 — `System.out.println(obj)`가 출력 시 자동 호출 |
| `Class getClass()` | 객체 자신의 클래스 메타정보(Class 객체) 리턴 |

재정의하지 않은 기본 `toString()`은 `클래스명@16진수해시코드` 형태(예: `java.lang.Object@1dbd16a6`)를 출력한다.

### equals() / hashCode() 재정의

`String`처럼, 객체의 **주소가 아니라 내용(데이터)**으로 동등 비교를 하고 싶다면 `equals()`를 재정의해야 한다.

```java
public class Member {
    private int id;
    private String name;

    @Override
    public boolean equals(Object obj) {
        if (obj instanceof Member target) {   // 패턴 매칭 instanceof (Java 16+)
            return name.equals(target.name) && id == target.id;
        }
        return false;
    }

    @Override
    public int hashCode() {
        return id + name.hashCode();   // equals에 쓰인 필드로 hashCode도 함께 재정의
    }
}
```

**중요한 규칙**: `equals()`를 재정의하면 **`hashCode()`도 반드시 함께 재정의**해야 한다 — "동등한 객체(`equals`가 true)는 반드시 같은 `hashCode()` 값을 가져야 한다"는 계약이 있기 때문(해시 기반 컬렉션인 `HashMap`/`HashSet`이 이 계약에 의존). 반대로 `hashCode()`가 같다고 해서 `equals()`가 반드시 true인 것은 아니다(해시 충돌 가능).

## record (Java 16+)

**데이터를 저장·전달하는 용도**에 최적화된 타입. `class` 대신 `record` 키워드를 사용하고, 저장할 데이터를 클래스 이름 뒤에 매개변수처럼 선언한다.

```java
public record Person(String name, int age) {}
```

이 한 줄이 컴파일되면 자동으로 생성되는 것:
- `private final` 필드 (`name`, `age`) — **불변(immutable)**
- 모든 필드를 받는 생성자
- 필드명과 같은 이름의 getter (`name()`, `age()` — `get` 접두사 없음)
- `equals()`, `hashCode()`, `toString()` — 모든 필드 값 기준으로 자동 구현(재정의도 가능)

```java
public record Staff(String name, int age, String email) {
    @Override
    public String toString() {                     // 필요하면 재정의 가능
        return String.format("[%s, %d, %s]", name, age, email);
    }
}
```

동일한 기능을 일반 `class`로 작성하려면 필드 선언, 생성자, getter, `equals`/`hashCode`/`toString` 재정의를 모두 손으로 작성해야 하므로, **불변 데이터 객체(DTO)** 용도라면 record가 훨씬 간결하다. 단, record는 **다른 클래스를 상속할 수 없다**(다른 클래스를 extends 불가 — 데이터 저장 전용이라는 설계 의도 때문).

## System 클래스 보충

[[12. 파일, 스트림과 직렬화|12장]]에서 다룬 `System.in`/`out`/`err` 외에 알아둘 정적 메서드:

```java
System.exit(0);                       // 프로세스 강제 종료 (관례: 정상 0, 비정상 1 또는 -1)
long t = System.currentTimeMillis();  // 1970-01-01 0시 기준 경과 밀리초
long n = System.nanoTime();           // 나노초 단위 경과 시간 — 실행 시간 측정에 더 정밀
String os = System.getProperty("os.name");   // 시스템 속성 조회(java.home, user.name 등)
```

`System.in.read()`로 키를 한 글자씩 읽을 때는 Enter 키가 Windows에서는 `\r`(13)과 `\n`(10) 두 글자로, Mac/Linux에서는 `\n`(10) 한 글자로 들어온다는 점에 주의.

## Wrapper 클래스 보충

[[13. 제네릭 컬렉션|13장]]에서 다룬 오토박싱 외에, 문자열 변환에 자주 쓰이는 메서드:

```java
int i = Integer.parseInt("123");           // 문자열 → 기본 타입
String s = Integer.toString(123);          // 기본 타입 → 문자열
String hex = Integer.toHexString(28);      // 16진수 문자열로 ("1c")
String bin = Integer.toBinaryString(28);   // 2진수 문자열로 ("11100")
```

```java
Math.abs(a); Math.max(a, b); Math.sqrt(a); Math.ceil(a); Math.floor(a); Math.round(a);

int num = (int)(Math.random() * n) + start;   // start ~ start+n-1 사이 정수 하나

Random random = new Random();        // 매번 다른 seed(현재 시간 기반) → 실행마다 다른 값
Random fixed = new Random(3);        // 고정 seed → 항상 같은 순서의 난수(테스트에 유용)
int r = random.nextInt(45) + 1;      // 1~45 사이 정수 (로또 번호 등)
```
