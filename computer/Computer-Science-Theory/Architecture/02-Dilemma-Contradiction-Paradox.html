논리학의 핵심 개념인 '딜레마', '모순', '역설'에 대한 정의를 알아보고, 이를 일상적 언어에서의 사용과 대조하여 알아본다.
먼저 논리학에서 딜레마가 타당한 논증을 이끄는 추론을 위해 사용된다면, 일상생활에서는 이를 ‘불가피한 선택지 사이의 갈등’이라는 맥락에서 선택에 초점을 두고 있음을 살펴본다. 특히 수업 중 다루어진 아키텍처 선택 사례가 일상적 딜레마의 개념으로 설명될 수 있음을 본다.
이어 모순의 개념을 간단히 정리한 뒤, '암달의 법칙'과 '구스타프슨의 법칙'이 수업 내에서 '역설'의 형식으로 설명되었음을 살펴본다. 이를 통하여 두 가지의 차이점을 더 잘 나타내기 위한 설명방식을 제안하고자 한다.

1. 딜레마, 모순, 역설의 정의와 예시 ​

1-1 딜레마란? ​

논리학(고대 그리스 수사학)에서 논증하기 위해 나온 개념 (방식)
두 가지 전제 중 어떤 전제를 골라도 동일한 결론이 이끌어지는 방법
조건문()과 선언문(or)의 결합으로 이뤄짐

기본적인 형태:

  1. ( 이거나 이다)
  2. ( 라면 이다)
  3. ( 라면 이다)

확장된 예시 (복합 구성적 딜레마) ​

(딜레마 + 가언 삼단논법)을 통한 예시
가령, '학생 A가 학생으로서 부적절한 태도를 지녔다'는 '무조건적인' 주장을 하려는 경우

: 학생 A가 수업중에 질문을 한다.
~ : 학생 A가 수업중에 질문을 하지 않는다.
: 수업의 흐름을 끊고 진도를 늦추는 방해꾼이다.
: 수업에 참여하지 않는 (관심이 없는) 학생이다.
: 부적절한 태도를 지녔다

  1. ~ ( 학생 A가 질문을 하든 안하든 )
  2. ( 질문을 한다면 방해꾼이다. )
  3. ~ ( 질문을 하지 않는다면 수업에 관심이 없는 학생이다. )
  4. ( 방해꾼이라면 부적절한 태도를 지닌 것이다. )
  5. ( 수업에 관심이 없다면 부적절한 태도를 지닌 것 이다. )
    ( 학생 A는 부적절한 태도를 지녔다! )

딜레마 논증을 통해 어떤 전제를 선택하더라도 같은 결론이 나옴을 보일 수 있다!

논증을 반박하는 방식 ​

(대표적인 경우 두가지)
각 전제를 황소의 양 뿔에 비유하여 반박하는 방식을 설명한다.

  1. 뿔 피하기 ( 제3의 경우 제시 )
    두 가지 경우 외에 또 다른 경우가 있음을 주장
    트롤리 딜레마의 경우 : 브레이크를 잡으면 모두를 살릴 수 있다고 주장
    앞선 수업 예시의 경우 : 수업이 끝나고 질문 하면 문제가 되지 않는다고 주장

  2. 뿔 잡기 ( 전제자체를 공격 ):
    전제 자체의 타당성을 비판
    앞선 수업 예시의 경우 : 적절한 질문은 오히려 수업에 도움이 된다고 전제 를 비판

일상 생활에서 딜레마의 개념 (증명 -> 선택) ​

논리학에서 딜레마가 두 전제를 통해 필연적인 결론을 증명하는 도구였다면, 일상생활에서의 딜레마는 이미 '어떤 선택을 하든 부정적인 결과를 피할 수 없다'는 암묵적 결론을 전제한 채, 그 사이에서 '최선의 대안'을 고민하는 과정으로 바라보는 것 같아 보임.

  • 트롤리 딜레마의 예시: ( 레버를 당길 것인가 VS 당기지 않을 것인가 )
    어떤 선택을 하든 불만족스럽다는 결론을 가정하고 두 가지 전제 중에 선택함에 집중

    • 구조: "선로를 바꾸든, 그대로 두든 결국 인명 피해는 발생한다."

    • 일상적 접근: 논증의 결과보다 '내가 레버를 당겨 직접적인 가해자가 될 것인가, 아니면 방관하여 더 큰 피해를 묵인할 것인가'라는 도덕적 책임의 무게를 선택하는 데 집중하고 있음

수업에서의 사례 (결론) ​

  • 상황: 아키텍처 A(MIPS 성능 우위) vs 아키텍처 B(Execution Time 성능 우위)
    "어떤 아키텍쳐를 선택하든 '절대적인 우위'를 증명하지 못하지 못한다"는 결론을 두고 "프로젝트의 우선순위(상황)에 비추어 볼 때, 어느 쪽의 손실을 더 감당할 수 있는가?"를 선택하는 과정으로 볼 수 있음
    이러한 관점에서 충분히 일생생활에서 사용하는 딜레마로 표현할 수 있어보임

1-3 역설 ​

"참인 전제들로부터 출발했음에도 불구하고, 타당한 추론을 거쳐 모순된 결론에 도달하는 논증"

  2. 가 거짓이라면, 내용이 부정되므로 는 참이다. ()
  3. (참이면서 동시에 거짓인 모순 발생)

일상생활에서의 역설 ​

"상식적으로는 모순되어 보이지만, 실제로는 깊은 진리를 내포하고 있는 현상"

  • 구조: 모순된 상황을 제시하여 기존의 단편적인 시각을 뒤집음으로 내포된 의미를 강조하기 위해 사용

왜 논리적 오해를 불러 일으킬 수 있음에도 사용하는가?
표면적 모순의 해결을 통하여 이면에 있는 의미를 강조하기 위해!

예시

  1. 도가 철학에서의 역설
    무위무불위(無爲無不爲): "아무것도 하지 않지만(無爲), 하지 못하는 것이 없다(無不爲)."
    표면적 모순을 포함

    내포된 의미: 무욕(욕심부리지 않으면, 인위적인 힘을 행하지 않으면)하면 되지 않는 일이 없다.

    무위와 무불위라는 모순된 개념 두가지를 각각 '위'에 대한 다른 해석을 통해 무욕을 역설적으로 강조함

  2. 문학에서의 역설
    유치환의 시 <깃발> 중 "이것은 소리 없는 아우성" 구문

    구조적 모순: '소리 없음(정적)'과 '아우성(소란)'은 논리적으로 양립할 수 없음

    내포된 의미: 깃발이 바람에 격렬하게 흔들리지만 소리를 낼 수 없는 상태는 '표현하고 싶지만 억눌린 내면의 갈망'을 시적으로 나타냄

    논리적으로는 불가능한 '소리 없는 아우성'이라는 표현을 통해, 인간의 고독과 의지를 역설적으로 강조함

수업시간의 예시 ​

암달의 법칙(Amdahl's Law) 과 구스타프슨의 법칙(Gustafson's Law) 의 경우 "cpu개수를 늘리면 성능이 linear하게 좋아지는가?"에 대한 질문에 대해 각각의 개별적 논리는 정당하나 서로 모순된 의견을 말하고 있는 것처럼 보이는 역설적 상황에 당면해 있음

1. 암달의 법칙(Amdahl's Law): 선형적 향상의 부정 ​

  • 전제: 문제의 크기가 고정되어 있음.

  • 논리: 전체 작업 내 순차적 처리 부분은 병렬화가 불가능하며, CPU를 늘려도 이 순차적 부분이 전체 실행 시간을 지배함.

  • 결론: CPU 개수를 무한히 늘려도 병목 현상으로 인해 선형적인 성능 향상은 불가능

2. 구스타프슨의 법칙(Gustafson's Law): 선형적 향상의 긍정 ​

  • 전제: 문제의 크기가 자원(CPU 개수)에 비례하여 늘어남.

  • 논리: 자원이 늘어난 만큼 문제의 규모도 함께 커지면, 전체 작업 내 순차적 부분이 차지하는 비중은 상대적으로 줄어듦.

  • 결론: 더 큰 규모의 문제를 처리할 때, CPU 개수 증가에 따라 선형적인 성능 향상을 기대할 수 있음

결론 (표면적 모순의 해소와 내포된 의미 파악) ​

수업 시작 단계에서는 두 법칙이 단순히 선형적 향상의 긍정과 부정의 모습으로서 모순되는 의견처럼 보였으나, 전제를 분석함으로 역설이 해소됨

  • 암달의 법칙: 고정된 작업을 빨리 끝내야 하는 Latency의 관점에서 유효
  • 구스타프슨의 법칙: 고정된 시간 내에 작업을 처리하는 Throughput관점에서 유효

병렬화의 성능이 선형적인지의 여부는 해결하고자 하는 문제의 정의(Problem Definition)에 달려 있음을 보이며, 서로 다른 전제로부터 이끌려 나왔기에 모순 관계로 볼 수 없음.

2. 차이점을 잘 나타내기 위한 설명방식 ​

앞서 보았듯 역설은 표면적 모순을 통해 그 이면에 내포된 본질적 의미를 강조하기 위해 사용됩니다. 그러나 암달의 법칙과 구스타프슨의 법칙을 설명하는 기존 자료들은 이러한 모순의 해소 과정을 비교를 통해 보여주기보다, 단지 두 법칙을 각각 나열하는 방식에 그치고 있어 그 역설적 의미가 충분히 드러나지 않는 것 같습니다.

1_3 수업자료
![[Amdahl_vs_Gustafson_Law.png]]
암달의 법칙과 구스타프슨의 법칙사이에는 처리량과, 시간적 전제의 차이가 있음에도 두 자료에서 시각적으로 그것을 대조적으로 표현해주고 있지 않는 것처럼 보입니다.

개선 방안: 역설의 논리적 시각화
두가지 방안 중 하나를 기준 삼아 두 예시를 표현한다면 조금 더 차이를 잘 드러낼 수 있을 것 같습니다.

방안 1 - 실행 시간 단축의 표현: 암달의 법칙에서 CPU 증가에 따른 병렬화 구간의 실행 시간 단축을 사각형 도형의 수직적 높이(간격) 차이를 통해 표현합니다. 이를 통해 '고정된 작업'이 시간적으로 어떻게 압축되는지 시각화합니다.

방안 2 - 처리량 차이의 강조: 암달의 법칙과 구스타프슨의 법칙 도식 간에 도형의 전체 크기를 다르게 설정합니다.
- 암달의 법칙과 구스타프슨의 법칙 사이의 작업 규모의 차이(도형의 너비 및 면적 증가)를 드러냄으로 둘이 다른 상태에 있음을 강조.

이와 같이 '무엇을 고정하고 무엇을 확장하는가'라는 전제 차이를 도형의 크기 변화를 통해 직관적으로 대비시킨다면, 두 법칙이 모순 관계가 아님을 명확히 나타낼 뿐만 아니라 각각의 특징을 강조할 수 있어 보입니다.
